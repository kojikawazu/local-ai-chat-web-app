# 会話の分岐 設計書

> 最終更新: 2026-10-31

会話の途中の応答から「ここから分岐」で、そこまでのやり取りを**新しい会話にコピー**し、別の方向で続けられるようにするための設計（#29。サブ issue #215）。会話の中をツリーにする案（issue の当初の案）は採らない。

## 背景

長い会話の途中で「この答えの後、別の聞き方を試したい」「ここまでの前提を保ったまま、別の方向に進めたい」と思っても、今は同じ会話の末尾に足していくしかない。末尾に足すと、試した方向のやり取りが履歴に残り、後の応答がそれに引きずられる。最初から聞き直すと、ここまでの前提（会話の役割・調べた結果・コード）を作り直すことになる。

応答の位置から、そこまでのやり取りを持った新しい会話を作れれば、元の会話はそのまま残し、分かれた先で別の方向を試せる。

## ツリーではなくコピーにする理由

| | 新しい会話にコピー（**この設計**） | 会話の中でツリー（issue の当初の案） |
|---|---|---|
| 分岐した先 | 別の会話（サイドバーに並ぶ） | 同じ会話の中の枝（`‹ 1/2 ›` で切り替える） |
| メッセージの保存の形 | **今のまま**（1 本の列） | `parentMessageId` で親子にし、表示する枝を覚える |
| 直す範囲 | 分岐の API・ボタン・分岐元のリンク | 読み込み・履歴の組み立て・再生成・検索・書き出し・ブックマークの移動先・削除のすべて |
| 元の会話 | まったく変わらない | 枝が増える |
| 向いている使い方 | 「ここから別の方向を試す」 | 「同じ質問の答えを何通りも見比べる」 |

このアプリには送ったメッセージを直して送り直す機能が無く、再生成は最後の応答だけを上書きする。ツリーにして得られる「枝の見比べ」を使う場面がまだ少なく、直す範囲に見合わない。コピーなら、今の会話の機能（検索・書き出し・ブックマーク・タイトル）が分岐した会話でもそのまま動く。

## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| 応答の下の「ここから分岐」のボタン | 会話の中のツリー・枝の切り替え |
| そこまでのメッセージ・添付画像・ツールの記録を、新しい会話にコピーする API | user のメッセージから分岐する（質問を直して送り直す） |
| 分岐した会話のヘッダーの「分岐元」のリンク（押すと元の会話のその応答へ移る） | 再生成で前の応答を残す |
| サイドバーの分岐した会話の印 | 分岐の系図の表示 |

## 決めること（レビューの論点）

| 論点 | 推奨 | 他の案 | 理由 |
|---|---|---|---|
| 分岐の形 | **新しい会話にコピー** | 会話の中でツリー | [上の表](#ツリーではなくコピーにする理由)。2026-10-31 に決定済み |
| 分岐できる位置 | **保存済みの assistant の応答だけ**（その応答までを含めてコピー） | user のメッセージからも分岐する（その手前までをコピーし、質問を入力欄に入れる） | 応答の後なら、分かれた先ですぐ次の質問を打てる。質問を言い直したいときは、1 つ前の応答から分岐すればよい。user のメッセージからの分岐は、添付画像を入力欄に戻す仕組みが要る |
| 最後の応答からの分岐 | **できる**（会話全体のコピーになる） | 最後の応答では出さない | 「ここまでを保ったまま、続きを 2 通り試す」に使える |
| 生成中の会話 | **分岐のボタンを押せない**（その会話の生成・承認待ちが終わるまで） | 保存済みの応答なら押せる | 生成中は最後の応答が保存されておらず、どこまでがコピーされるか分かりにくい |
| 分岐元の覚え方 | **`Conversation.forkedFromMessageId`**（分岐した応答への外部キー。消えたら `null`） | 会話の ID と応答の ID の 2 列 | 応答から会話は引けるので 1 列で足りる。元の会話を消せば Conversation → Message と消え、分岐した会話の参照は `null` になる（分岐した会話は残る） |
| コピーする中身 | **本文・metadata（思考・ツールの記録・トークン数）・添付画像・作成日時** | 本文だけ | 分かれた先でも、ツールの結果や画像を見ながら続けたい。LLM へ送る履歴も元の会話と同じになる |
| 添付画像 | **中身ごとコピーし、新しい ID を振る**。ツールの画面の ID（`metadata.toolCalls[].screenshots[].id`）も新しい ID に書き換える | 元の画像を共有する | `Attachment` は 1 つのメッセージに属する。共有にすると、元の会話を消したときに分岐した会話の画像が消える |
| ブックマーク | **コピーしない** | コピーする | 印は元の応答に付けたもの。同じ印が 2 つの会話に出ると、一覧が重複する |
| タイトル | **`元のタイトル（分岐）`**。もう `（分岐）` で終わっていれば足さない。100 文字に収める | LLM でタイトルを作り直す | 分岐した直後は中身が元と同じ。分かれた先で質問しても、最初のやり取りではないので自動のタイトル生成は動かない（今の作りのまま）。名前を変えたいときは後で直す（#29 では足さない） |
| 会話の役割 | **コピーする** | 役割なしで始める | 前提を保ったまま続けるのが目的 |
| 分岐した後 | **新しい会話を開き、入力欄にフォーカスする** | 元の会話に留まり、お知らせだけ出す | 押した目的は分かれた先で続けること |
| 分岐元を消したとき | **分岐した会話は残り、分岐元のリンクだけ消える** | 分岐した会話も消す | 分岐した会話は独立した会話。消すかどうかは利用者が決める |

## データ

```prisma
model Conversation {
  // …今の列
  forkedFromMessageId String?   // 分岐した応答（#29）。分岐していない会話・分岐元が消えた会話は null
  forkedFromMessage   Message?  @relation("ConversationFork", fields: [forkedFromMessageId], references: [id], onDelete: SetNull)

  @@index([forkedFromMessageId])
}

model Message {
  // …今の列
  forkedConversations Conversation[] @relation("ConversationFork")
}
```

- マイグレーションは `add_conversation_fork`。今の会話は `null` のまま（分岐していない）。
- 元の会話を消すと、Conversation → Message のカスケード削除で応答が消え、分岐した会話の `forkedFromMessageId` は `SetNull` で `null` になる。
- 再生成は応答の行を置き換える（ID は同じ）ため、分岐元の参照は残る。リンクを押すと、再生成した後の応答へ移る。

## API

### `POST /api/conversations/[id]/fork`

| 項目 | 内容 |
|---|---|
| ボディ | `{ messageId: string }`（分岐する応答の UUID） |
| 201 | `{ conversation }`（会話一覧の 1 件と同じ形。`forkedFrom` 付き） |
| 400 | 会話・メッセージの ID の形が不正・ボディが不正・user のメッセージを指定した（`分岐できるのは応答だけです`） |
| 404 | 会話が無い・メッセージがその会話に無い・コピーの途中で応答が消えた（外部キーの違反 `P2003` を `isForeignKeyConstraintError()` で 404 にする） |
| 500 | 保存の失敗 |

- 検証の順序はほかの route と同じ（ID の形・ボディ → DB）。
- コピーは 1 つのトランザクションで行う（会話の作成・メッセージ・添付画像。途中で失敗したら何も残さない）。
- メッセージは、会話の表示と同じ順（`createdAt` の昇順）に読み、分岐する応答の位置までを取る。

### `GET /api/conversations`（変更）

各会話に `forkedFrom` を足す。

```ts
forkedFrom: { conversationId: string; messageId: string; title: string } | null;
```

- 分岐元の会話のタイトルは、応答から会話をたどって引く（1 回のクエリの `select` で取る）。
- `POST /api/conversations`（作成）の応答にも `forkedFrom: null` を入れ、一覧の 1 件と形を揃える。

## コピーの中身

| 項目 | 扱い |
|---|---|
| メッセージの ID | 新しい UUID |
| 本文・role | そのまま |
| `createdAt` | **元のまま**（表示の時刻と並び順を保つ。この後に送るメッセージは今の時刻になるので、必ず後ろに並ぶ） |
| `metadata` | そのまま。ただし `toolCalls[].screenshots[].id` は、コピーした添付画像の新しい ID に書き換える |
| 添付画像 | 中身・形式・寸法・並び順をそのままに、新しい ID でコピーする |
| ブックマーク | コピーしない |
| 会話のタイトル | `元のタイトル（分岐）`（[論点](#決めることレビューの論点)） |
| 会話の役割 | そのまま |
| 会話の `updatedAt` | 今の時刻（サイドバーの一番上に並ぶ） |

- ID の書き換え（`remapScreenshotIds`）とタイトル（`toForkTitle`）は純ロジックにし、UT で確かめる。
- `metadata` の形の検証は今の `parseMessageMetadata` と同じ考え方で、`toolCalls` が配列でない・`screenshots` の要素が形に合わないものは、そのまま残す（コピーは「元と同じもの」を作る。表示の側が今と同じく捨てる）。

## 画面

### 応答の下の「ここから分岐」

- 応答の操作の行（コピー・ブックマーク・再生成の並び）に、`GitBranch` のアイコンのボタンを足す（`IconButton`。ラベル「ここから分岐」）。
- 出す条件: 保存済みの assistant の応答（`saveState` が無い）。その会話が生成中・承認待ちの間は押せない（`disabled`）。
- 押すと API を呼び、返事を待つ間はボタンを押せない（二度押しで 2 つ作らない）。
- 成功したら、会話一覧を読み直し、新しい会話を開いて入力欄にフォーカスする。
- 失敗したら、画面のお知らせ（`notice`）に `会話を分岐できませんでした` を出す（元の会話はそのまま）。

### ヘッダーの分岐元のリンク

- 分岐した会話を開いている間、ヘッダーの役割のボタンの隣に `⑂ 分岐元: <タイトル>` のボタンを出す（長いタイトルは省略して `title` 属性で全体を見せる）。
- 押すと元の会話を開き、分岐した応答まで移って枠で示す（ブックマークの「元の応答へ移る」（#30）の `focusTarget` をそのまま使う）。
- 分岐元が消えた会話（`forkedFrom` が `null`）では出さない。

### サイドバーの印

- 分岐した会話の行のタイトルの前に、小さな `GitBranch` のアイコンを出す（`aria-label`「分岐した会話」）。

## やらないこと

- 会話の中のツリー・兄弟の枝の切り替え（`‹ 1/2 ›`）
- user のメッセージから分岐する（質問を直して送り直す）。質問を言い直すときは、1 つ前の応答から分岐する
- 再生成で前の応答を残し、見比べる
- 分岐の系図（どの会話からどの会話が分かれたか）の表示。分岐元へのリンクは 1 段だけ
- 会話のタイトルの手での変更（別の issue）
- 書き出し（Markdown・JSON）に分岐元を書く
- 会話の検索で、分岐した会話と元の会話の重複をまとめる（同じ本文が 2 つの会話に出る）
