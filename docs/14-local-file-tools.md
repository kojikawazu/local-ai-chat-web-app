## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| フォルダの中身の一覧（`list_directory`） | ファイルの作成・編集（Phase A2） |
| ファイル名・中身の検索（`search_files`） | コマンドの実行（Phase B） |
| ファイルの読み取り（行の範囲を指定できる。`read_file`） | GitHub の PR の操作（Phase C） |
| 許可したフォルダの中だけに限ること・秘匿ファイルを読ませないこと | 実行前に利用者の承認を挟む UI（Phase A2・B で作る） |
| ローカルのファイルを読んだ応答の中では、外部へ送るツールを止めること | 正規表現での検索 |

ツールはエージェントモード（設定の「ツールを使う」）のときだけ使える。既存のツールと同じ扱い。

## 前提の調査

2026-10-26、Ollama 0.40.5・`qwen3.8:27b`・64GB の Apple Silicon Mac で確かめた。

### コンテキストの長さと読む速さ

- Ollama が実際に確保しているコンテキストの長さは 262,144 トークン（`/api/ps` の `context_length`）。長さそのものは足りる。
- **入力を読む速さは 1 秒あたり 100〜130 トークン程度**。ソースコード 8,000 文字（約 2,900 トークン）を読ませると、答え始めるまでに 23 秒かかった。
- エージェントループは、ラウンドごとにそれまでのツールの結果を含めて Ollama へ送る（同じ応答の中では先頭が同じなのでキャッシュが効き、増えた分だけ読まれる）。

→ ファイルを丸ごと渡すと、1 回の読み取りで 1 分以上待たされうる。**1 回に返す量に上限を付け、続きは行の範囲を指定して読ませる**（[上限値](#上限値)）。

### 履歴への残り方

- ツールの結果は、その応答の metadata（`toolCalls`）として DB に保存され、画面のツールの結果の欄に出る。
- 次の質問で LLM へ渡す会話履歴は本文（`role`・`content`）だけで、ツールの結果は含まれない（`lib/chat/conversation-history.ts`）。ただし応答の本文にファイルの中身が引用されていれば、それは履歴として残る。

### 使える Node の機能

- CI の Node は 20 / 22。`fs.glob` は Node 22 からのため使わず、フォルダは `fs.promises.readdir`（`withFileTypes`）で自前にたどる。
- ripgrep などの外部コマンドには頼らない（入っているとは限らない。コマンド実行は Phase B の範囲）。

## 脅威と方針

ローカル LLM とはいえ、ツールを呼ぶ判断はモデルがする。モデルは利用者の指示だけでなく、**Web 検索・URL 取得の結果や、読んだファイルの中に書かれた指示**にも従いうる（プロンプトインジェクション）。

| 脅威 | 例 | 対策 |
|---|---|---|
| 許可していない場所を読む | `../../.ssh/id_rsa`・シンボリックリンクで外へ出る | 許可するフォルダを環境変数で明示し、**実体のパス**（`realpath`）で中にあるかを判定する（[パスの判定](#パスの判定)） |
| 許可したフォルダの中の秘匿ファイルを読む | プロジェクトの `.env`・鍵ファイル | 秘匿ファイルの名前は検索にも出さず、読み取りも拒否する（[読ませないファイル](#読ませないファイルたどらないフォルダ)） |
| 読んだ中身を外へ送る | ページに仕込まれた指示で、読んだ値を `url_fetch` の URL に埋めて送る | **ローカルのファイルを読んだ応答の中では `web_search`・`url_fetch` を止める**（[外部への持ち出しを止める](#外部への持ち出しを止める)） |
| 大きなファイル・フォルダで止まる | `node_modules` を全部たどる・巨大なログを読む | たどらないフォルダ・件数・バイト数・時間の上限（[上限値](#上限値)） |
| 書き換え・実行 | — | Phase A は読み取りだけで、書き込み・実行の手段を持たない |

**既定では使えない**: `LOCAL_FILE_ROOTS` を設定していなければ、3 つのツールはモデルに渡さない（`GET /api/tools` にも出さない）。利用者が自分で範囲を決めて初めて使えるようにする。

## ツール

3 つとも結果は文章（モデルへ返す）と、画面の見出しに出す要約（`summary`）を返す。失敗も例外にせず `toolError` で返す（既存のツールと同じ）。

### `list_directory`（フォルダの中身）

| 引数 | 必須 | 説明 |
|---|---|---|
| `path` | ○ | 一覧を出すフォルダの絶対パス（許可したフォルダの中） |

- 直下の項目だけを、フォルダ → ファイルの順・名前順で返す（再帰しない）。ファイルにはバイト数を付ける。
- 秘匿ファイル・たどらないフォルダは出さない（出さなかった件数は書く）。
- `path` を省いたときの既定は置かない（モデルが許可したフォルダを知らないため、エラーの文章で許可したフォルダの一覧を返す）。
- 要約: `12 件`

### `search_files`（ファイルを探す）

| 引数 | 必須 | 説明 |
|---|---|---|
| `query` | ○ | 探す文字列 |
| `path` | ○ | 探し始めるフォルダの絶対パス（許可したフォルダの中） |
| `target` | — | `name`（ファイル名）か `content`（中身）。既定は `name` |

- `name`: ファイル名に `query` を含むもの（大文字・小文字を区別しない）。`*` と `?` を含む場合はワイルドカードとして扱う（`*.ts` 等。正規表現は受けない）。
- `content`: 中身に `query` を含む行（大文字・小文字を区別しない、文字列の一致）。行番号と、その行の前後を切り詰めた本文を返す。バイナリ・大きすぎるファイルは飛ばす。
- 正規表現は受け付けない（モデルが組んだ式で極端に遅くなる（ReDoS）のを避ける。必要になったら別に検討する）。
- 見つかった数が上限に達したら、そこで打ち切って「上限に達した」と書く。
- 要約: `8 件`（打ち切ったら `30 件以上`）。0 件は `isEmpty`（⚠️）

### `read_file`（ファイルを読む）

| 引数 | 必須 | 説明 |
|---|---|---|
| `path` | ○ | 読むファイルの絶対パス（許可したフォルダの中） |
| `start_line` | — | 読み始める行（1 始まり。既定 1） |
| `end_line` | — | 読み終わる行（含む。既定は `start_line` から上限の行数まで） |

- 行番号付きで返す（モデルが続きの範囲を指定しやすいように）。上限で切れたら、全体の行数と「続きは `start_line` に N を指定」と書く。
- UTF-8 として読む。先頭 8KB に NUL が含まれるファイルはバイナリとして読まない。
- 要約: `README.md（1〜120 行目 / 全 340 行）`

## 許可するフォルダ（LOCAL_FILE_ROOTS）

| 環境変数 | 説明 | 既定 |
|---|---|---|
| `LOCAL_FILE_ROOTS` | ツールが読んでよいフォルダの絶対パス。複数はカンマ区切り。`~` で始まればホームに置き換える | 未設定（ツールを使わない） |

- 起動時に 1 度だけ解釈する（変えたら開発サーバーを再起動する。`SEARXNG_URL` 等と同じ）。
- 各フォルダは `realpath` で実体のパスにしてから持つ。存在しない・フォルダでない・相対パスのものは、`console.warn` で知らせて外す（`AGENT_MAX_TOOL_ROUNDS` の不正値と同じ扱い）。全部外れたらツールを使わない。
- **ホームそのもの（`~`）や `/` も指定はできる**が、`.env.example` と `docs` には「プロジェクトのフォルダなど、必要な範囲だけを指定する」と書く。止めはしない（使う人の判断のため）。
- 例: `LOCAL_FILE_ROOTS=~/developer/claude/local-ai-chat-web-app,~/notes`

## パスの判定

ツールに渡されたパスは、次の順で確かめる（`lib/agent/tools/local-files/path-guard.ts`）。

1. 文字列であること・絶対パスであること・NUL を含まないこと。相対パスは拒否する（どこからの相対かをモデルが取り違えるため）。
2. `realpath` で実体のパスにする（シンボリックリンク・`..` をすべて解決する）。存在しなければ「見つからない」。
3. 実体のパスが、許可したフォルダ（の実体のパス）のどれかの中にあることを、`path.relative` で確かめる（結果が `..` で始まらず、絶対パスでもない）。文字列の前方一致では判定しない（`/a/b` と `/a/bc` を取り違えるため）。
4. 途中のどの階層も、秘匿ファイル・読ませないフォルダの名前でないこと（[次節](#読ませないファイルたどらないフォルダ)）。

フォルダをたどるとき（`search_files`）は、**シンボリックリンクをたどらない**（`readdir` の `Dirent` がリンクなら飛ばす）。たどると、許可したフォルダの外や、循環に入りうるため。

判定の中心（実体のパス同士の包含・名前の判定）は fs に触れない純関数にして UT で確かめる。`realpath` を含む一連の流れは、一時フォルダに実際のファイル・シンボリックリンクを作って IT で確かめる。

## 読ませないファイル・たどらないフォルダ

**秘匿ファイル**（検索・一覧に出さず、読み取りも拒否する）:

- 名前: `.env`・`.env.*`（`.env.example` / `.env.sample` / `.env.template` / `.env.dist` は除く）、`*.key`・`*.pem`・`*.p12`・`*.pfx`・`*.jks`・`*.keystore`、`id_rsa`・`id_ed25519`・`id_dsa`（`.pub` は除く）、`credentials.json`・`serviceAccountKey.json`
  - CI の Secret scan（`.github/workflows/secret-scan.yml` の `SECRET_PATTERN` / `ALLOW_PATTERN`）と同じ範囲にする。同じ事実が 2 か所に書かれるため、`documentation.md` の「重複している事実」の表に足す。
- フォルダ: `.ssh`・`.gnupg`・`.aws`・`.kube`・`.docker`（中の認証情報を丸ごと守る）

**たどらないフォルダ**（検索で中に入らない。読み取りは許す）: `node_modules`・`.git`・`.next`・`dist`・`build`・`coverage`・`.venv`・`__pycache__`・`.turbo`・`.cache`

- 生成物・依存で量が多く、検索の上限をすぐに使い切るため。指定すれば中のファイルを直接読むことはできる（`node_modules` の型定義を読む等）。

## 外部への持ち出しを止める

同じ応答（1 回のエージェントループ）の中で、ローカルのファイルのツール（3 つのどれか）が**成功した後は、`web_search`・`url_fetch` を実行しない**。

- 実行しようとしたら、ツールの結果として「ローカルのファイルを読んだ後は、外部への通信を止めています」と返す（`toolError`。`unavailable` の印を付け、同じ応答では呼び直させない。#157 の仕組みを使う）。
- 逆の順（Web を見てからファイルを読む）は止めない。Web の結果に仕込まれた指示でファイルを読んでも、そこから外へ送る手段が無くなるため。
- 次の質問（別の応答）では、またどちらも使える。応答の本文に引用された中身は履歴に残るため、完全な遮断ではない。より強い遮断（会話単位で止める・承認を挟む）は Phase A2・B の承認の仕組みと合わせて検討する。
- 判定はエージェントループ（`lib/agent/agent.ts`）が持つ。ツールには「ローカルを読むツール」「外部へ送るツール」の印（`ToolDefinition` の外の、ループだけが読む情報）を付ける。止めたツールは、#157 の「同じ応答では使えないツール」の一覧（`unavailableTools`）に入れて扱う。
- 後の段階で、コマンドの実行（Phase B の `run_command`）と GitHub を読むツール（Phase C。非公開のリポジトリの内容を読むため）にも「ローカルを読むツール」（`access: 'local'`）の印を付けた。止めたときの文章は「ローカルのファイル・コマンドの出力・GitHub の内容を読んだため」になっている（[17-github-tools.md](./17-github-tools.md#外部への持ち出しとの関係)）。

## 上限値

| 対象 | 上限 | 根拠 |
|---|---|---|
| `read_file` の 1 回の行数 | 300 行 | ソースコードで 1 回 約 10,000 文字に収まる量 |
| `read_file` の 1 回の文字数 | 12,000 文字 | 約 4,000 トークン・読むのに 30 秒程度（[前提の調査](#前提の調査)） |
| `read_file` で開くファイルの大きさ | 2MB | 行を数えるために全体を読むため。超えたら読まない |
| `search_files` の見つかった数 | 30 件 | 一覧を読ませる量を抑える |
| `search_files` で中身を見るファイルの大きさ | 1MB | 超えたら中身の検索では飛ばす |
| `search_files` でたどるファイルの数 | 5,000 件 | 許可したフォルダが大きくても、時間の上限より先に止める |
| `search_files` の 1 行の表示 | 200 文字 | 圧縮された JS などの 1 行が長いファイル |
| `list_directory` の項目数 | 200 件 | — |
| 時間 | `AGENT_TOOL_TIMEOUT_MS`（既定 30 秒） | 既存のツールと同じく `signal` で止める。たどる途中でも `signal` を確かめる |

値はツールの中だけで使うため、各ツールのファイルの先頭に置く（`validation.ts` の上限は画面と API が共有するものに限る）。

## 画面

- ツールの見出しのラベル（`constants/chat/toolLabels.ts`）: `list_directory` → 「フォルダを見る」、`search_files` → 「ファイルを探す」、`read_file` → 「ファイルを読む」
- 結果の表示は既存のツールの結果の欄（`ToolCallResult`）のまま。要約（`summary`）を見出しに出し、展開で全文を出す。
- ツールの一覧の API（`GET /api/tools`）には、`LOCAL_FILE_ROOTS` を設定しているときだけ出る（画面はこの一覧を使っていない）。
- 承認の UI は作らない（読み取りだけのため。Phase A2 で作る）。

## ファイル構成

```
front/src/lib/agent/tools/
├── local-files/
│   ├── config.ts        # LOCAL_FILE_ROOTS の解釈（realpath・不正値の警告）
│   ├── path-guard.ts    # パスの判定（包含・秘匿ファイル・たどらないフォルダ）。中心は純関数
│   ├── text.ts          # バイナリの判定・行の切り出し・切り詰め（純関数）
│   ├── list-directory.ts
│   ├── search-files.ts
│   └── read-file.ts
└── registry.ts          # LOCAL_FILE_ROOTS があるときだけ 3 つを登録する
```

- エージェントループ（`agent.ts`）に「ローカルを読んだ後は外部へ送るツールを止める」判定を足す。
- `process.env.LOCAL_FILE_ROOTS` を読むのは `config.ts` だけにする。

## テスト

| 層 | 対象 |
|---|---|
| UT | 包含の判定（`..`・前方一致の取り違え・ルートそのもの）・秘匿ファイルの名前（`.env` と `.env.example`・`id_rsa` と `.pub`）・ワイルドカードの変換・バイナリの判定・行の切り出しと切り詰め・`LOCAL_FILE_ROOTS` の解釈（カンマ・`~`・相対パス）・持ち出しの判定 |
| IT | 一時フォルダに実際のファイルを作り、3 つのツールを実行する: 一覧・名前と中身の検索・行の範囲の読み取り・上限での打ち切り・**シンボリックリンクで外へ出られない**・秘匿ファイルを読めない・許可の外のパス・存在しないパス。エージェントループで、ローカルを読んだ後の `url_fetch` が止まること（Ollama はスタブ） |
| E2E | `local-files.spec.ts`: `GET /api/tools` に 3 つが出る（CI でも動く）。実際にファイルを探して読ませ、結果の欄に要約が出る（ツール呼び出しが要るため `IS_LIGHT_MODEL` でスキップ） |

- E2E の dev サーバーには `playwright.config.ts` の `webServer.env` で `LOCAL_FILE_ROOTS` に E2E 用のフォルダ（`tests/e2e/fixtures/local-files/`）を渡す。
- IT は DB を使わないが、fs という実際の依存を相手にするため IT に置く（fs をモックすると、モックの動きを確かめるだけになる）。

## やらないこと

- **書き込み・実行・承認の UI**: Phase A2・B。
- **正規表現での検索**: ReDoS の対策が要るため。文字列の一致とワイルドカードで足りなければ検討する。
- **`.gitignore` に従った除外**: パターンの解釈を正しく実装する手間に見合わない。たどらないフォルダの固定の一覧で代える。
- **会話単位での持ち出しの遮断**: 承認の仕組み（Phase A2・B）と合わせて検討する。
- **Windows のパス**: 開発機は macOS（`manuals/setup-guide-macos.md` と同じ範囲）。
