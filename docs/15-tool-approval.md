# ツールの承認とファイルの書き込み 設計書

> 最終更新: 2026-10-26

## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| ファイルの作成・上書き（`write_file`）・部分の置き換え（`edit_file`） | 削除・名前の変更・フォルダの作成 |
| 書き込む前に差分を見せて、利用者が「許可 / 拒否」を選ぶ承認 | 「この応答では全部許可」などの一括の承認 |
| 承認の待ち時間の上限・停止での取り消し | 書き込みの取り消し（元に戻す） |
| 承認の仕組みを、後のツール（コマンドの実行等）でも使える形にする | コマンドの実行（Phase B） |

## 承認の流れ

エージェントループ（`/api/chat` のストリーム）の中で、承認が要るツールの実行の手前で止まって待つ。

```
モデルが write_file / edit_file を呼ぶ
  ↓ ① 準備（prepare）: 引数・パス・上限を確かめ、差分を作る。失敗ならここで理由を返す（承認は求めない）
  ↓ ② tool_approval_request イベントを送る（承認 ID・ツール名・差分）
  ↓ ③ ループは承認の結果を待つ（最大 5 分。ストリームは開いたまま）
画面: 承認カードを出す → 利用者が「許可」か「拒否」を押す
  ↓ POST /api/agent/approvals/[id]  { approved: true | false }
  ↓ ④ 許可なら実行（run）: 準備した時点からファイルが変わっていないことを確かめてから書く
  ↓    拒否・時間切れ・停止なら書かずに、その旨をモデルへ返す
  ↓ ⑤ tool_call_result（承認の結果を含む）を送り、ループを続ける
```

### 方式の決定: ストリームを開いたまま待つ

| 観点 | 開いたまま待つ（採用） | いったん閉じて、承認後に送り直す |
|---|---|---|
| 実装 | 承認待ちをサーバーのメモリに持ち、Promise で待つ | ループの途中の状態（履歴・ツールの結果）を保存して、続きから再開する仕組みが要る |
| 停止・切断 | 既存の `signal` がそのまま効く（待ちを取り消す） | 再開しないことで止まる |
| 制約 | サーバーのプロセスが 1 つであること | なし |

localhost の個人利用で、サーバーのプロセスは 1 つのため、開いたまま待つ方式を採る。

- 承認待ちは `lib/agent/approvals.ts` が `globalThis` の `Map`（承認 ID → 結果を渡す関数）に持つ。Next.js の開発サーバーでは route ごとにモジュールが別に読み込まれることがあり、モジュールの変数では `/api/chat` と承認の API の間で共有されないため（Prisma のクライアントと同じ置き方）。
- 承認 ID は `crypto.randomUUID()`。承認の API は、知らない ID・決着済みの ID を 404 にする。

### ツールの形の拡張

承認が要るツールは、実行を「準備」と「実行」に分ける（`Tool` に任意の `prepare` を足す）。

```ts
type ApprovalPreview = {
  action: 'create' | 'overwrite' | 'edit';  // 作成・上書き・部分の置き換え
  path: string;                              // 実体のパス
  diff: string;                              // unified diff
  summary: string;                           // 見出し（「README.md を編集（+3 −1）」）
};

type PreparedAction =
  | { ok: true; preview: ApprovalPreview; run: (signal: AbortSignal) => Promise<ToolExecution> }
  | { ok: false; output: ToolExecution };     // 準備で失敗（承認は求めない）
```

- `prepare` を持つツールは、エージェントループが承認を挟んでから `run` を呼ぶ。`prepare` を持たないツールは今までどおり `execute` を呼ぶ。
- ツールの実行時間の上限（`AGENT_TOOL_TIMEOUT_MS`）は、`prepare` と `run` にそれぞれ掛ける。承認を待つ時間には掛けない（人が読む時間のため）。

### 承認の結果

| 結果 | モデルへ返す文章 | 画面の見出し |
|---|---|---|
| 許可して書けた | 「〜を書き込みました（+3 −1 行）」 | ✅ `README.md を編集（+3 −1）` |
| 拒否 | 「利用者が拒否したため書き込みませんでした。理由を聞くか、別の方法を提案してください」 | ❌ `拒否されました` |
| 時間切れ（5 分） | 「承認が得られなかったため書き込みませんでした」 | ❌ `承認されませんでした（時間切れ）` |
| 停止・切断 | （ループごと止まるため返さない） | — |
| 承認の間にファイルが変わった | 「承認の間にファイルが変わったため書き込みませんでした。読み直してください」 | ❌ |

- 拒否・時間切れは同じ応答の中で同じツールを止めない（別の内容なら承認できるため）。
- 承認の結果は `ToolCallInfo` に `approval`（`approved` / `rejected` / `expired`）として残し、保存する。

## ツール

### `write_file`（作成・上書き）

| 引数 | 必須 | 説明 |
|---|---|---|
| `path` | ○ | 書き込むファイルの絶対パス |
| `content` | ○ | ファイルの中身の全体 |

- 無ければ作成、あれば上書き（上書きは差分で見せる）。親のフォルダは既にあること（フォルダは作らない）。
- 既存のファイルがバイナリ・2MB 超なら上書きしない。

### `edit_file`（部分の置き換え）

| 引数 | 必須 | 説明 |
|---|---|---|
| `path` | ○ | 編集するファイルの絶対パス |
| `old_string` | ○ | 置き換える前の文字列（ファイルの中にちょうど 1 か所だけあること） |
| `new_string` | ○ | 置き換えた後の文字列 |

- `old_string` が 0 か所・2 か所以上なら、理由を返して承認を求めない（2 か所以上なら、前後の行を足して 1 か所に絞るよう返す）。
- 改行が CRLF のファイルでは、`old_string`・`new_string` の `\n` を `\r\n` に揃えてから探す（`read_file` は行を分けて返すため、モデルは `\r` を含めない）。

## 書き込んでよい場所（LOCAL_FILE_WRITE_ROOTS）

| 環境変数 | 説明 | 既定 |
|---|---|---|
| `LOCAL_FILE_WRITE_ROOTS` | 書き込んでよいフォルダの絶対パス（カンマ区切り・`~` 可） | 未設定（書き込みのツールを使わない） |

- 読み取りの `LOCAL_FILE_ROOTS` とは別に決める。読むだけの範囲（`~/developer` 全体等）と、書いてよい範囲（作業中のリポジトリだけ）を分けられるように。
- 書き込むフォルダは、読み取りのフォルダの中にあること（中に無いものは `console.warn` で外す）。書く前に `read_file` で中身を確かめられるようにするため。
- 新しいファイルはまだ無いため、**親のフォルダ**を `realpath` で実体にしてから包含を判定し、名前を足す。既にあるファイル（シンボリックリンクを含む）は、ファイルそのものを `realpath` で実体にして判定する。

## 差分の表示

- 差分は npm の `diff`（jsdiff。`^9.0.0`、版はロックファイルで固定）の `createTwoFilesPatch` で unified diff にする。自前の差分の計算は持たない（行の対応づけ（Myers のアルゴリズム）を正しく実装するのは手間に見合わない）。
- 承認カードには差分を 400 行まで出し、超えたら「ほか N 行」と書く（全体は承認できる。モデルへ返す文章には差分を入れない）。

## 画面

- **承認カード**（`ApprovalCard`。`features/chat/molecules`）: 生成中の応答の一番下（今の「ツール実行中」の表示の位置）に出す。
  - 見出し: 「ファイルを作成します」「ファイルを上書きします」「ファイルを編集します」と、パス
  - 本文: 差分（追加の行は緑、削除の行は赤。等幅）
  - ボタン: 「許可」（主な操作）・「拒否」
- 同じラウンドで複数の承認が来たら、1 枚ずつ順に出す（待っている数を書く）。
- 承認待ちは会話ごとの状態（`chat-state`）に持つ。別の会話を開いている間も待ち続け、戻ると承認カードが出る（サイドバーの生成中の印も出たまま）。
- 押したらカードを消し、結果はツールの結果の欄に出る（✅ / ❌）。
- 停止ボタンを押すと、承認待ちも取り消す（書かない）。

## 上限値

| 対象 | 上限 | 根拠 |
|---|---|---|
| `write_file` の `content` | 200,000 文字 | モデルがこれを超える量を一度に書くのは現実的でない（出力が遅い）。誤って巨大な文字列を書かせない |
| 編集・上書きする既存のファイル | 2MB | `read_file` と同じ |
| 承認の待ち時間 | 5 分 | 席を外していてもすぐには取り消さない長さ。ストリームを開いたまま待つため、際限なくは待たない |
| 承認カードの差分の表示 | 400 行 | — |

## 脅威と対策

| 脅威 | 例 | 対策 |
|---|---|---|
| 指示を仕込まれて書き換える | Web の結果に「この設定ファイルを書き換えて」 | **書き込みは毎回、差分を見せて利用者が許可してから**。一括の許可は作らない |
| 実行されるファイルを書き換える | `.git/hooks/pre-commit` を書いて、次の `git commit` で実行させる | `.git` の中には書かせない（読み取りは許す）。ほかに実行されうるファイル（シェルの設定・CI の定義等）は、書き込んでよい場所を作業中のリポジトリに限ることと承認で守る |
| 秘匿ファイルを書き換える・作る | `.env` を書き換える | 秘匿ファイル・秘匿フォルダ（Phase A と同じ範囲）には書かせない |
| 許可していない場所に書く | `..`・シンボリックリンクで外へ出る | 親のフォルダ（新規）・ファイル（既存）を実体のパスにしてから判定する |
| 承認の後に中身をすり替える | 承認した差分と違う内容を書く | 準備で作った中身をそのまま書く。準備した時点のファイルの中身（ハッシュ）と、書く直前の中身が違えば書かない |
| 承認の API を外から叩く | 別のサイトから `POST /api/agent/approvals/[id]` | 承認 ID は推測できない UUID で、待っている間だけ有効。localhost の個人利用で認証は無い（既存の API と同じ前提） |

## ファイル構成

```
front/src/
├── lib/agent/
│   ├── approvals.ts                  # 承認待ちの登録・決着・時間切れ・取り消し（globalThis の Map）
│   ├── agent.ts                      # prepare → 承認 → run の流れを足す
│   └── tools/local-files/
│       ├── write-guard.ts            # 書き込み先の判定（新規は親のフォルダ・.git・秘匿）
│       ├── diff.ts                   # 差分の作成と行数の集計（jsdiff）
│       ├── write-file.ts
│       └── edit-file.ts
├── app/api/agent/approvals/[id]/route.ts  # POST: 許可 / 拒否
├── components/features/chat/molecules/ApprovalCard.tsx
└── hooks/chat/useChat.ts             # tool_approval_request を受け、承認の API を呼ぶ
```

- `AgentStreamEvent` に `tool_approval_request`（`approvalId`・`name`・`preview`）を足す。決着は続く `tool_call_result` で分かるため、別のイベントは足さない。
- `ToolCallInfo` に `approval?: 'approved' | 'rejected' | 'expired'` を足す。

## テスト

| 層 | 対象 |
|---|---|
| UT | 承認待ちの登録・決着・時間切れ・取り消し（偽のタイマー）・`edit_file` の一致の数え方と CRLF・書き込み先の判定（新規・`.git`・秘匿）・差分の行数・結果の文章 |
| IT | `/api/chat`（Ollama はスタブ）と承認の API を合わせて: 許可で書ける・拒否で書かない・時間切れ・停止で取り消し・準備と実行の間にファイルが変わったら書かない・`old_string` が 0 / 2 か所・`.git` と秘匿ファイルを断る・知らない承認 ID は 404・書き込みの場所が無ければツールを登録しない |
| E2E | 承認の API の 404・400（CI でも動く）。実際にモデルにファイルを書かせ、承認カードの差分・許可・拒否（大きいモデルだけ。`IS_LIGHT_MODEL` でスキップ。E2E 用のフォルダの複製に書く） |

## やらないこと

- **一括の承認**（「この応答の間は全部許可」）: 指示を仕込まれたときに守りが外れるため。使ってみて要るとなれば、範囲を絞って検討する。
- **削除・名前の変更・フォルダの作成**: 必要になったら同じ承認の仕組みで足す。
- **書き込みの取り消し**: Git で戻せる場所（作業中のリポジトリ）に限ることで代える。
- **承認待ちの保存**: ページを読み直すとストリームが切れ、承認待ちは取り消しになる（停止と同じ）。
