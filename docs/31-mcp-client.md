## 背景

- 今のツール（Web 検索・ローカルのファイル・コマンドの実行・GitHub・ブラウザ等）は、すべてアプリの中に実装している。外部サービスを足すたびにツールを自前で書くのは重い
- MCP の既存のサーバーをつなげば、ツールを書かずに外部サービスを使える
- #34（プラグインシステム）は、独自の定義の形式で HTTP のエンドポイントをツールにする案で、「外からツールを足す」目的が重なる

今ある仕組みのうち、次を使う。

- **実行前の承認**（#148 Phase A2）: `Tool.prepare` → 承認カード → `run`
- **外部への持ち出しの抑止**（#148）: `Tool.access` と `shouldBlockTool`。ただし MCP のツールにはそのまま当てられない（[外部への持ち出し](#外部への持ち出し)）
- **`globalThis` の待ち合わせ**（#148 Phase A2・#241）: route ごとにモジュールが別に読み込まれても、接続を共有する
- **未設定なら登録しない**（`LOCAL_FILE_ROOTS`・`GITHUB_REPOS` と同じ）

## 調査で分かったこと

2026-11-04 に、リポジトリの外の使い捨ての環境で確かめた（SDK は `@modelcontextprotocol/sdk` 1.32.2・Node 24・Next.js 16.4.2）。

### SDK の挙動（手元のサーバー・stdio）

| 確かめたこと | 結果 |
|---|---|
| 接続の時間 | 89 ms（自作の小さいサーバー。`npx` で起動するサーバーは測っていない） |
| 入れ子の引数の JSON Schema | そのまま取れる（先頭に `$schema` が付く） |
| 子プロセスの環境変数 | 既定で `HOME`・`LOGNAME`・`PATH`・`SHELL`・`TERM`・`USER` だけを渡す。親の `DATABASE_URL` は渡らなかった |
| 引数の間違い・無いツール | 例外にならず `isError: true` の結果で返る（`MCP error -32602: ...`）。モデルへそのまま返せる |
| ツールの失敗 | `isError: true` の結果で返る |
| 画像の結果 | `content` に `{ type: 'image', data, mimeType }` が混ざる |
| 中断（`signal`）・時間切れ（`timeout`） | どちらも指定どおり約 300 ms で `McpError`（`-32001`）を投げ、サーバーにも取り消しが届く |
| `client.close()` | 子プロセスが止まる |
| サーバーの異常終了 | `onclose` が呼ばれ、以降の呼び出しは `Not connected` を投げる |
| 起動できないコマンド | `connect()` が `ENOENT` を投げる |

### Next.js の Route Handler

| 確かめたこと | 結果 |
|---|---|
| バンドル | `serverExternalPackages` の設定なしで、`next dev`・`next build` とも通る |
| 接続の使い回し | `globalThis` に置くと、リクエストをまたいで同じプロセスを使う |
| ホットリロード | route のファイルを変えても接続は残る（プロセスは増えない） |
| 開発サーバーの終了 | 子プロセスも止まる（孤児が残らない） |

### モデルの挙動（`qwen3.8:27b`）

組み込みに近い 4 個 + MCP を想定した 5 個（Jira・Slack・Drive。`mcp__jira__search_issues` の形の名前）に、無関係のツールを足して数を変え、4 つの依頼で測った。

| ツールの数 | ツールの選択 | 引数（入れ子・配列・列挙を含む） | プロンプトのトークン数 |
|---|---|---|---|
| 9 | 4/4 | 4/4 | 955 |
| 34 | 4/4 | 4/4 | 2,665 |
| 64 | 4/4 | 4/4 | 4,715 |
| 124 | 4/4 | 4/4 | 8,795 |

- 選択と引数は、`mcp__<サーバー>__<ツール>` の名前・入れ子のスキーマとも問題なかった。文脈の上限は 262,144 トークンで、ツールの一覧であふれる心配は無い
- **この結果は上限の根拠としては弱い**: 足したツールは名前が明らかに無関係で、説明も短い（1 個あたり約 70 トークン）。似た名前のツールが並ぶ実際のサーバーでは、選び間違いもトークン数も悪くなりうる。依頼も 4 つだけ
- **速さへの影響は測れていない**: 各数の最初の依頼は 28 秒（34 個）・44 秒（64 個）・77 秒（124 個）と増えたが、124 個でも 2 つ目の依頼は 9 秒だった。思考の時間と、プロンプトのキャッシュ・最初のモデルの読み込みが混ざっている
- 実際の公開の MCP サーバー（Atlassian 等）には繋いでいない。ツールの数・説明の長さは Phase B の後に実物で測る

## 範囲

| 含める（Phase B） | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| 手元のサーバー（stdio）への接続 | リモートのサーバー（HTTP）と OAuth（Phase C） |
| 設定ファイルでつなぐサーバーを決める | 画面からサーバーを足す・変える |
| サーバーのツールをエージェントのツールにする（ツールごとに絞れる） | サーバーの `resources`・`prompts`・`sampling` |
| 書き込みのツールの実行前の承認 | 画面でのサーバー・ツールごとの ON / OFF（使ってから決める） |
| 読んだ出どころごとの持ち出しの抑止 | サブエージェントへ MCP のツールを渡す |
| つないだサーバーの状態の表示 | 結果の画像をモデルへ渡す |

## 決めること（レビューの論点）

2026-11-04 のレビューで、すべて推奨どおりに決めた。

| # | 論点 | 推奨 | ほかの案 | 理由 |
|---|---|---|---|---|
| M1 | #34 との関係 | **MCP で置き換える**。独自の形式は作らず、#34 は理由を残して閉じる | 別に残す | 目的が同じで、MCP なら既存のサーバーが使える。HTTP のエンドポイントをツールにしたければ小さい MCP サーバーを書けばよい |
| M2 | 設定の置き場所 | **JSON の設定ファイル**。パスを環境変数 `MCP_CONFIG_PATH` で渡す。形は広く使われている `mcpServers` に合わせる | 環境変数だけ / 画面の設定 | コマンド・引数・環境変数の入れ子は環境変数に収まらない。他のクライアントの設定を写せる。プログラムを起動する設定なので、`KNOWLEDGE_VAULTS` と同じく画面からは足せないようにする |
| M3 | Phase の順 | **手元のサーバー（stdio）を先に入れ、HTTP と OAuth は Phase C** | 同時に入れる | issue の想定どおり。OAuth はトークンの保存・更新・取り消しの設計が大きく、手元のサーバーだけでも使い始められる |
| M4 | 秘密の渡し方 | 設定の `env` の値に **`${NAME}` を書き、`.env.local` の値を入れる** | 設定ファイルに直接書く | 設定ファイルに秘密を置かずに済む。書いた名前だけを渡すので、`DATABASE_URL` 等は渡らない |
| M5 | 承認の要否 | **`readOnlyHint: true` のツールだけ承認なし。注釈が無いものも含めてほかはすべて承認**。設定の `alwaysApprove` で、読むツールにも承認を求められる | すべて承認 / 利用者が読むツールを列挙する | 注釈の既定は「書き込みかもしれない」で、安全な側に倒れる。注釈はサーバーの申告で保証ではないが、手元のサーバーは利用者が選んで動かすプログラムで、嘘をつくならどの道いろいろできる。リモートのサーバー（Phase C）は改めて決める |
| M6 | 持ち出しの抑止 | **読んだ出どころを集合で持ち、同じサーバーの続きの操作だけを通す**（[外部への持ち出し](#外部への持ち出し)） | 今の真偽値のまま | 真偽値のままだと、Jira で検索した直後の 2 回目の Jira の読み取りが止まり、使い物にならない |
| M7 | 読んだ後の、別の出どころへの書き込み | **承認が要るツールは通す**（Jira を読んで Slack へ送る使い方ができる）。承認カードに「この応答で読んだもの」を出す。承認の無いツールは止める | 承認があっても止める | `github_comment`・`run_command` と同じ考え方（`docs/17-github-tools.md`「書くツールは承認が守り」）。送る内容は利用者が見て決める。止めるとサーバーをまたぐ使い方ができない。ただし読んだ内容に仕込まれた指示で本文が細工されうるため、承認カードの確認が唯一の守りになる。止める案はブラウザの操作（手元を読んだ後は公開のページを操作しない）に近く、より安全だが不便 |
| M8 | ツールの数 | 設定の **`tools` でサーバーごとに絞れる**ようにし、全体の上限を **40 個**にする。超えた分はモデルへ渡さず画面に出す | 上限なし / 画面で ON / OFF | 124 個でも選べたが、測り方が甘い（[モデルの挙動](#モデルの挙動qwen3827b)）ため、控えめな値から始めて実物で見直す。40 は測った値から導いたものではなく、最初の目安 |
| M9 | 登録の方法 | **応答の始めに非同期で同期する**（`syncMcpTools()`）。同期の `initializeTools()` は変えない | 起動時に接続する | ツールの一覧の取得は非同期で、使わない人の起動を遅くしない。失敗しても応答は止めない |
| M10 | 結果の画像 | **モデルへ渡さず、省いたことを文章で伝える** | `images` で渡す | 画像を読めないモデルの分岐が要る。使ってから決める |

## 設定

`MCP_CONFIG_PATH` に JSON のファイルの絶対パス（`~` 可）を書く。未設定なら何もつながず、ツールも登録しない。

```json
{
  "mcpServers": {
    "jira": {
      "command": "/usr/local/bin/jira-mcp",
      "args": ["--read-write"],
      "env": { "JIRA_TOKEN": "${JIRA_TOKEN}" },
      "cwd": "/Users/me/work",
      "tools": ["search_issues", "get_issue", "create_issue"],
      "alwaysApprove": ["get_issue"]
    }
  }
}
```

| 項目 | 必須 | 意味 |
|---|---|---|
| キー（`jira`） | ○ | サーバーの名前。`^[a-z0-9_-]{1,32}$`。ツールの名前の一部になる |
| `command` | ○ | 起動するプログラム。シェルを介さない |
| `args` | | 引数 |
| `env` | | 足す環境変数。値の `${NAME}` はアプリの環境変数で置き換える。無ければそのサーバーは「設定の誤り」にする |
| `cwd` | | 作業フォルダ（絶対パス） |
| `tools` | | 使うツールの名前。省略すると全部 |
| `alwaysApprove` | | 読むツールでも承認を求めるツールの名前 |

`url` など知らない項目があれば、そのサーバーは使わず「設定の誤り」にする（Phase C の設定を黙って無視しないため）。設定ファイルは読むだけで、アプリの起動後の最初の応答で 1 度読む（変えたらアプリを再起動する）。

## 接続とツールの登録

```
/api/chat → runAgentLoop → syncMcpTools()
                              ├ 設定を読む（初回だけ）
                              ├ 未接続のサーバーへ接続（並べて・10 秒まで）
                              ├ ツールの一覧を取る（ページを最後まで）
                              └ レジストリの mcp__ のツールを置き換える
                           → getAllToolDefinitions() → Ollama へ
```

- 接続は `lib/agent/tools/mcp/connections.ts` が `globalThis` に持つ（`/api/chat` と `/api/tools` で共有し、ホットリロードで増やさないため）。応答ごとには接続しない
- `Client` には capabilities を宣言しない（`sampling`・`elicitation`・`roots` をサーバーへ渡さない）
- 標準エラーは `stderr: 'pipe'` で受ける（SDK の既定の `inherit` はログへそのまま流れる）
- 接続に失敗したサーバーは、状態を `failed` にして飛ばす。応答は止めない。同じサーバーへの次の接続は 30 秒待つ（送るたびに 10 秒待たせないため）
- サーバーが落ちたら（`onclose`）状態を戻し、次の応答で接続し直す
- `notifications/tools/list_changed` が届いたら、次の応答で一覧を取り直す
- **レジストリは `syncMcpTools()` がモジュールごとに同期する**。レジストリはモジュールの変数で route ごとに別になりうるため、接続は共有し、一覧の反映はそれぞれのモジュールで行う
- 名前は `mcp__<サーバー>__<ツール>`。ツールの名前は `[a-zA-Z0-9_-]` 以外を `_` にし、全体を 64 文字までにする。ぶつかったら後のものを渡さず画面に出す。元の名前はツールの中に持ち、サーバーへはそれで送る
- 上限（40 個）を超えた分は、設定に書いたサーバーの順・サーバーが返した順で後ろから外す
- 応答の途中でレジストリから消えたツールが呼ばれたら、失敗の結果で返す（別の応答の同期で消えることがある）
- `ToolDefinition.parameters` の型は入れ子を表せないため、値の型を JSON Schema の形に広げる（`$schema` は外す）

## ツールの実行

- **読むツール**（`readOnlyHint: true` で `alwaysApprove` に無い）: `execute` で実行する
- **それ以外**: `prepare` を持ち、承認の後に実行する
- 引数の検証はサーバーに任せる（間違いは `isError` で返り、モデルが読んで直せる）
- `signal` と `timeout` を SDK へ渡す。時間の上限は `AGENT_TOOL_TIMEOUT_MS`（SDK の既定の 60 秒より短い）
- 結果の変換: `text` をつなぐ。`image`・`audio`・`resource` は「（画像を省きました）」の形で文章に置き換える。`isError` は `toolError`。接続が切れていれば `toolUnavailable`（同じ応答では呼び直さない）
- 結果は 12,000 文字で切る（`read_file` と同じ）

## 外部への持ち出し

### 今の規則で足りないこと

今は `access: 'local'` のツールが成功すると、以降の `access: 'network'` のツールを止める。MCP のツールは、どちらか一方ではない。

- Jira を読むツールは、非公開の情報を読む（`local` の性質）し、引数は外へ出る（`network` の性質）
- どのサーバーが何に触れるかは、アプリから分からない（手元のサーバーでも裏で外部と通信しうる）

そこで、**すべての MCP のツールを両方の性質を持つものとして扱う**。ただし今の真偽値のまま当てると、Jira を読んだ後の 2 回目の Jira の読み取りが止まる。

### 読んだ出どころの集合

`hasReadLocal` の真偽値を、読んだ出どころの集合にする。

- `Tool` に `origin?: string` を足す（MCP のツールは `mcp:<サーバー>`）
- ループは `access: 'local'` の成功で `'local'` を、MCP のツールの成功で `mcp:<サーバー>` を、集合に足す。書くツールの成功も足す（結果に何が返るかアプリから分からないため）
- `access: 'network'` のツールは、**集合に自分の `origin` 以外があり、承認が要らないなら止める**（`shouldBlockTool` に `origin` と承認の有無を足す）
- 承認が要るツールは止めず、承認カードに「この応答で読んだもの」（Jira・手元の情報 等）を出す
- `ToolContext.hasReadLocal()` は「集合が空でない」のまま残す（ブラウザのプロキシ等は変えない）

| 先に読んだもの | 次に呼ぶもの | 結果 | 理由 |
|---|---|---|---|
| Jira | Jira（読む・書く） | 通す | 情報はもともとそのサーバーのもの |
| Jira | Slack の読むツール | 止める | 引数に自由な文字列を書け、承認なしで外へ出る |
| Jira | Slack の書くツール | 承認の後に通す | 送る内容を利用者が見て決める（M7） |
| Jira | `github_comment`・`run_command` | 承認の後に通す | 今の規則のまま（`access` が `network` ではない） |
| Jira | `web_search`・`url_fetch`・公開のページ | 止める | 外部への持ち出し |
| Jira | `read_file` 等の手元のツール | 通す | 手元を読むのは持ち出しではない。ただしこの後は Jira の読むツールも止まる |
| `read_file`・RAG の抜き出し | Jira の読むツール | 止める | 手元の情報の持ち出し |
| `read_file`・RAG の抜き出し | Jira の書くツール | 承認の後に通す | M7 |
| `web_search` | Jira | 通す | 公開の情報を読んだだけ。ただし検索結果の中の指示には注意（[セキュリティ](#セキュリティ)） |

サブエージェントへの委譲は `origin` を持たないため、MCP のツールで読んだ後は `researcher`（`network`）に任せられない。ブラウザの操作も `hasReadLocal()` を見ているため、MCP のツールで読んだ後は公開のページを操作しない。どちらも今の規則のまま効く。

## 画面

- **承認カード**: `ApprovalPreview` に `mcp` を足す。サーバーの名前・ツールの元の名前・引数の JSON を文字のまま出す（Markdown として描かない）。この応答で読んだものがあれば、別の出どころへの送信だと分かるように出す（M7）。ツールの説明はサーバーの書いた文章なので出さない
- **ツールの見出し**: `mcp__jira__search_issues` は「jira: search_issues」の形にする（`tool-label.ts`）。引数の要約は今の仕組みのまま
- **設定**: つないだサーバーの一覧を出す。名前・状態（接続中 / 失敗 / 設定の誤り）・ツールの数・失敗の理由・上限で渡していないツールの数。`/api/tools` の応答に `mcp`（設定ファイルの誤りの `configError` とサーバーの `servers`）を足す（エンドポイントは増やさない）。今の画面は `/api/tools` を読んでいないため、読むフック（`hooks/settings/useMcpServers`）を足す

## 上限値

| 値 | 上限 | 理由 |
|---|---|---|
| つなぐサーバー | 10 | 子プロセスの数を抑える |
| モデルへ渡すツール | 40（全サーバーの合計） | M8 |
| ツールの説明 | 1,024 文字 | 長い説明で問い合わせを重くさせない。サーバーの書いた文章がモデルへ入る量も抑える |
| 接続の待ち時間 | 10 秒 | 応答の始めを長く止めない |
| 失敗の後の再接続 | 30 秒待つ | 送るたびに待たせない |
| 結果 | 12,000 文字 | `read_file` と同じ |

## セキュリティ

| 脅威 | 対策 |
|---|---|
| 設定を書き換えて任意のプログラムを起動する | 設定は `MCP_CONFIG_PATH` のファイルだけ。画面・API・モデルから変えられない |
| モデルに任意のプログラムを起動させる | モデルが決められるのはツールと引数だけ。`command` はモデルへ渡さない |
| アプリの秘密がサーバーへ渡る | SDK の既定の環境変数と、設定の `env` に書いた分だけを渡す（`DATABASE_URL` が渡らないことは確かめた） |
| 設定の秘密がリポジトリに入る | `${NAME}` で `.env.local` から入れる。設定ファイルはリポジトリの外に置くよう案内する |
| ツールの説明・結果の中の指示（プロンプトインジェクション） | 完全には防げない。本当の防ぎは承認と持ち出しの抑止。説明の長さを切り、承認カードには出さない |
| 接続の後でツールの説明が変わる | 書き込みは毎回承認を挟み、承認カードにはサーバーの説明ではなく実際の引数を出す。説明の変更の検知は入れない |
| 読んだ内容に仕込まれた指示で、別の出どころへの書き込みの本文を細工する | 承認カードに実際の引数と「この応答で読んだもの」を出す。利用者の確認が唯一の守り（M7） |
| 読むツールと申告して書き込む | M5 のとおり手元のサーバーは信頼する。心配なら `alwaysApprove` で承認を求める。リモートのサーバーは Phase C で決める |
| `npx -y` 等で起動するサーバーの中身が変わる | アプリでは防げない。版を固定して書くようマニュアルで案内する |
| サーバーの標準エラーに秘密が出る | そのままログに流さず、長さを切って接続の失敗の理由にだけ使う |

変える既存のファイル: `tools/types.ts`（スキーマの型・`origin`）、`tools/index.ts`（登録の解除）、`agent.ts`（`syncMcpTools()`・読んだ出どころの集合）、`app/api/tools/route.ts`、`tool-label.ts`、`ApprovalCard`、`SettingsModal`。

`@modelcontextprotocol/sdk` は版を固定して入れる。依存が 95 パッケージ・26 MB 増える（`express`・`hono` 等のサーバー側の依存も入る。使うのはクライアントだけ）。

## テスト

- **UT**: 設定の検証（`${NAME}`・知らない項目・名前の形）、名前の組み立てとぶつかり、40 個の上限、結果の変換、持ち出しの判定の表の全行（承認の有無を含む）
- **IT**: テストの中で起こす本物の stdio の MCP サーバー（`tests/integration/helpers/`）と実際の SDK で、登録 → 実行 → 結果、承認、持ち出しの抑止、サーバーの異常終了と接続し直し、接続の失敗でも応答が続くこと、環境変数が絞られること。Ollama はスタブ
- **E2E**: `webServer.env` の `MCP_CONFIG_PATH` で確認用のサーバーをつなぎ、設定の状態の表示を見る。ツールの呼び出しに依存するテスト（承認カード・実行）は `IS_LIGHT_MODEL` でスキップし、`qwen3.8:27b` で通す。外部サービスには触れない

## 実装で分かったこと

- **`waitForResponseComplete` はエージェントモードですぐ通過する**: 送信ボタンが押せるのを待つが、生成中でも「割り込む」（#241）で押せる。最初の `mcp.spec.ts` は、応答の途中で見出しを探して落ちた。「生成を停止」が消えるのを待つようにした。ほかのエージェントの spec は共通のヘルパーのままで、直していない
- **確認用のサーバーには `zod` が要る**: `McpServer` の `inputSchema` に使う。SDK の依存だが pnpm では `front` から読めないため、開発用の依存に足した（SDK が使うものと同じ版）
- **`next dev` の終了で子プロセスは残らなかった**: SDK で作ったサーバーで確かめたため、アプリの終了時に片付ける処理は足していない。SDK を使わないサーバーの動きは確かめていない

## やらないこと

- リモートのサーバー（HTTP）と OAuth（Phase C。トークンの保存・更新・取り消しと、`readOnlyHint` を信じるかを改めて決める）
- 画面からのサーバーの追加・編集（プログラムの起動の設定を画面から変えさせない）
- 画面でのサーバー・ツールごとの ON / OFF（使ってから決める）
- サーバーの `resources`・`prompts`・`sampling`（ツールだけを使う。`sampling` はサーバーがモデルを呼べる機能で、持ち出しの扱いが別に要る）
- サブエージェントへ MCP のツールを渡す（渡すツールはコードで決めている。使ってから決める）
- 結果の画像をモデルへ渡す（M10）
