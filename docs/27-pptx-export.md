## 背景

HTML スライド（#223）で、応答をそのままブラウザで発表できるようになった。ただ、受け取った人が社内のテンプレートに貼り直したり、文言を直してから発表したりするには、PowerPoint・Keynote・Google スライドで開いて編集できる PPTX の方が都合がよい。DOCX（#221）がレポートに対して果たす役割を、スライドに対して果たす。

## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| 応答 1 件の PPTX（見出し・段落・強調・リスト・表・コード・引用・リンク・図） | 会話全体の PPTX |
| HTML スライドと同じ分け方（`---`・見出し）と表紙の判定 | PowerPoint のテンプレート（スライドマスター）の選択 |
| 収まらない内容を続きのスライドへ送る | 発表者のノート・切り替えの動き |
| 応答の「保存」のダイアログに PPTX を足す | コードの色付け・添付画像 |

## 決めること（レビューの論点）

| 論点 | 推奨 | 他の案 | 理由 |
|---|---|---|---|
| どこで作るか | **ブラウザの中**（HTML スライド・DOCX と同じ） | issue の案の Route Handler（`GET /api/export/pptx`） | 図はブラウザで描く。図を描く → 組み立てる → 保存の流れをそのまま使える |
| ライブラリ | **npm の `pptxgenjs`**（4.0.1。2025-06 公開） | 自前で OOXML を書く（`jszip`） | 純粋な JavaScript でブラウザでも動く（issue の案どおり）。表・画像・ハイパーリンク・スライドマスターを持つ。自前は XML の量が多く、PowerPoint の修復のダイアログを避けるのが難しい |
| 読み込み方 | **PPTX を選んだときだけ読み込む**（`import('pptxgenjs')`） | 画面を開いたときに読み込む | DOCX・Mermaid と同じ。使わない人に読み込ませない |
| 対象 | **応答 1 件だけ**（応答の「保存」のダイアログ） | 会話全体も | HTML スライドと同じ理由（質問と応答が交互に並ぶ会話は発表の形にならない） |
| 変換の作り | **Markdown → 文書の中間の形（`DocBlock[]`。DOCX と共通）→ スライドに分ける（`splitSlides`。HTML スライドと共通）→ 割り付け（純関数）→ pptxgenjs の 4 段** | 中間の形から直接 pptxgenjs を呼ぶ | PPTX はスライドの中の位置と大きさをすべて自分で決める（HTML のように流し込めない）。割り付けを純関数にすれば、どの図形がどこに置かれ、何枚に分かれるかを pptxgenjs 抜きの UT で確かめられる |
| 分け方 | **HTML スライドと同じ**（`---` があればそこで、無ければ `max(最も浅い見出し, 2)` 段までの見出しで。front matter を除き、コメントだけの生の HTML を出さない） | — | 同じ応答から HTML スライドと PPTX を作ったとき、同じ枚数・同じ区切りになる |
| スライドのタイトル | **スライドの先頭が見出しなら、その見出しをスライドのタイトル（PowerPoint のタイトルの位置）にする**。先頭が見出しでなければタイトルなしで本文を上から置く | すべての見出しを本文の中に置く | PowerPoint のアウトライン表示・スライドの一覧でタイトルが見える。テンプレートを差し替えたときもタイトルの位置に移る |
| 収まらないスライド | **見積もった高さが本文の枠を超えたら、残りを続きのスライド（タイトルに「（続き）」）へ送る**。ブロックの境目で分け、リストは項目、表は行（見出しの行を繰り返す）、コードは行の単位で分ける | 文字を縮める（PowerPoint の自動調整） / はみ出したまま | HTML スライドはスライドを伸ばしたが、PPTX のスライドの大きさは決まっている。PowerPoint の「はみ出したら縮小」は開いて編集したときにしか計算されず、保存しただけのファイルでははみ出して見える。内容を欠けさせない |
| 高さの見積もり | **文字の幅を全角 1・半角 0.55 として行数を数え、フォントの大きさ × 行の高さで見積もる**（少し余裕を持たせる） | ブラウザの canvas で文字の幅を測る | 純関数のまま UT で確かめられる。PowerPoint のフォントとブラウザのフォントは違うため、測っても正確にはならない |
| 表紙 | **HTML スライドの表紙の判定（1 枚目が見出しと段落だけ）に従い、タイトルを中央に大きく、段落をサブタイトルにする**。本文が空なら会話のタイトルだけの表紙 1 枚 | 会話のタイトルの表紙を必ず足す | HTML スライドと同じ |
| 見た目 | **16:9（13.33 × 7.5 インチ）・白い背景・Nord の青のアクセント（HTML スライドと同じ色）・游ゴシック（英数字も）・コードは Consolas** | 暗い背景 | 印刷・プロジェクターで見やすい。受け取った人がテンプレートを当て直しやすい |
| フッター | **スライドマスターに、左に会話のタイトル、右に PowerPoint のスライド番号を置く** | 各スライドに「3 / 12」を文字で書き込む | 受け取った人がスライドを足し引きしても番号がずれない。全体の枚数は PowerPoint の番号の欄では出せないため出さない |
| コード | **等幅・薄い灰色の塗りの枠。色付けはしない** | rehype-highlight のクラスを文字の色にする | DOCX と同じ判断 |
| 図 | **DOCX と同じく PNG にして埋め込む**（`diagramsToPng`）。本文の枠の残りに収まるよう縮め、中央に置く。描けなければソースのコード | SVG のまま入れる | 古い PowerPoint・Keynote・Google スライドで見えるようにする |
| 添付画像 | **入れない**（HTML スライドと同じ） | 入れる | 応答の添付画像はブラウザのツールの画面で、本文の中には現れない |
| 新しい依存 | **`pptxgenjs` 4.0.1 だけ**（テストで中身を読む `jszip` は DOCX で dev に入れたもの） | — | 上のとおり |

## 書き出しの流れ

```
応答の「保存」のダイアログで PPTX を選ぶ
  → 図を拾って描く（HTML レポートと共通。useReportExport）→ 図の SVG を PNG にする（DOCX と共通）
  → 本文の先頭の front matter を取り除く（stripFrontMatter）
  → Markdown を文書の中間の形にする（markdownToBlocks。コメントだけの生の HTML を出さない指定）
  → スライドに分ける（splitSlides。DocBlock の種類を返す関数を渡す）
  → 割り付ける（純関数。スライドごとの図形の位置・大きさ。収まらなければ続きのスライド）
  → import('pptxgenjs') → 割り付けを図形にする → write({ outputType: 'blob' }) → `<タイトル>_<日時>.pptx` で保存
```

- 図の描画・失敗の扱い（描けなかった図はソースのコード）は HTML レポート・DOCX と同じ。PPTX の組み立てそのものの失敗だけダイアログにエラー。
- 中断した応答は、最後のスライドに「（生成を中断した応答）」の注記を置く。

## スライドの割り付け

単位はインチ（pptxgenjs の単位）。

| 枠 | 位置・大きさ |
|---|---|
| スライド | 13.33 × 7.5（16:9） |
| タイトル | 左右 0.6・上 0.4、高さ 1.0（32pt・太字・下に Nord の青の線） |
| 本文 | 左右 0.6、タイトルの下（タイトルなしは上 0.5）から下 6.7 まで |
| フッター | 下 7.0〜7.4（10pt・灰色。スライドマスター） |

- 本文のブロックは上から順に積む。ブロックの間は 0.15。
- **行の間隔は pt で固定する**（文字の大きさ × 1.4。`<a:lnSpc><a:spcPts>`）。フォントの既定の行の高さに任せると、游ゴシックは行の間が広く、見積もりより高くなってフッターに重なった（実装のときに Quick Look の描画で確かめた）。表のセルには固定の間隔を渡せない（pptxgenjs のセルの指定に無い）ため、行の高さを 1.5 倍で見積もり、その高さを PowerPoint の行の高さ（`rowH`）に指定する（文字が収まれば行は指定の高さになる）。
- テキストの続くブロック（段落・見出し・リスト・引用・注記）は 1 つずつ別のテキストボックスにする（PowerPoint で動かしやすく、高さの見積もりもブロックごとにできる）。
- 文字の大きさ: 段落・リスト 18pt、スライドの中の見出し 22pt（`###` 以降は 20pt）・太字、表 14pt、コード 13pt、注記 14pt。
- 1 つのブロックだけで本文の枠を超えるとき: リスト・表・コードは分けて続きのスライドへ。段落・引用は分けずにそのスライドに 1 つだけ置き、はみ出しを許す（PowerPoint の自動調整の指定も付ける）。図は枠に収まるまで縮める。
- 表紙: タイトルを上下の中央（40pt）、段落をその下にサブタイトル（20pt・灰色）。

## PowerPoint の部品への対応

| 中間の形 | PowerPoint |
|---|---|
| スライドの先頭の見出し | タイトル |
| 先頭以外の見出し | 太字の段落（本文のテキストボックス） |
| 段落（強調・斜体・取り消し線・インラインのコード・リンク・改行） | テキストボックスの段落（太字・斜体・取り消し線・Consolas・ハイパーリンク・改行） |
| リスト | 箇条書き・番号付き（入れ子は字下げの段階。番号付きは 1 つのリストの段落にすべて同じ `startAt`（連番の最初の番号）を付け、続きのスライドでは続きの番号にする。PowerPoint は連番の何番目かを数えて `startAt` に足すため、段落ごとに変えると 1, 3, 5… になる）。タスクは `☐` / `☑` を頭に付け、記号は付けない。項目の中のコード・表・引用は、その項目の文字として並べる（1 つのテキストボックスに入れるため） |
| 表 | 表（罫線付き。見出しの行は Nord の淡い色の塗り・太字。列の幅は等分） |
| コード | Consolas・薄い灰色の塗りのテキストボックス |
| 引用 | 左に Nord の青の細い四角、右に灰色の斜体のテキスト |
| 画像（描けた図） | PNG の画像（縦横比を保って縮め、中央） |
| 区切り線（リスト・引用の中に残ったもの） | 細い線 |
| 注記 | 灰色の小さい段落 |

- リンクは中間の形の時点で検査済み（`defaultUrlTransform`。危ない URL は付かない）のものだけをハイパーリンクにする。生の HTML は文字、本文の画像はリンクか文字（DOCX と同じ）。PPTX にはマクロ・スクリプトを入れない（`.pptx` はマクロを持てない形式）。

## ライブラリの注意点

- **Node 用の読み込み**: pptxgenjs の ES 版（`dist/pptxgen.es.js`）は、Node でファイルを読む処理の中で `import('node:fs')`・`import('node:https')` を持つ（ブラウザでは通らない）。`pnpm build`（Turbopack）でクライアントのバンドルが通り、dev サーバーのブラウザでも読み込めることを確かめた（`turbopack.resolveAlias` は要らなかった）。
- **依存の中身**: 実行時の依存に `@types/node`（^22。このアプリは ^20）と、中身の無い npm の `https` パッケージを持つ。`pnpm typecheck` で型が衝突しないことを確かめた。
- **指定のオブジェクトの書き換え**: pptxgenjs は、渡した文字の片の `options` に図形の指定を写して書き換える。文字の片ごとに新しいオブジェクトを渡す。段落の書式（箇条書き・字下げ）は段落の先頭の片から取られ、段落は `breakLine` で分かれる。段落の中の改行は次の片の `softBreakBefore`。
- **記号**: タスクの `☐` / `☑` は箇条書きの記号（`characterCode`）にする（記号なしの段落は字下げが 0 になり、入れ子を表せないため）。XML には `&#x2611;` の形で書かれる。
- **書き出し**: ブラウザでは `write({ outputType: 'blob' })` で Blob にし、既存の `downloadBlob` で保存する（pptxgenjs の `writeFile` はダウンロードの仕方を自分で持つため使わない）。
- **`image-size` の上書き（#231）**: pptxgenjs 4.0.1 は依存に `image-size` `^1.2.1` を持つが、配布のコード（`dist/*.js`）は読み込まない（使う関数がコメントアウトされ、`package.json` の `browser` でも `false`）。1.x に Dependabot の high の警告（GHSA-w3rx-r6r6-pgpr・GHSA-5p2g-fcmc-qvqq。2.0.3 で修正）があるため、`front/package.json` の `pnpm.overrides` で 2.0.3 より古い版を `^2.0.4` に上げている。pptxgenjs が `image-size` 2 以上を求める版に上げたら、この上書きを外す。
- **型**: `lib/chat/report-pptx.ts` は pptxgenjs の型だけを import し、本体は呼び出し側から受け取る（DOCX の `report-docx.ts` と同じ）。

## 画面

- 応答の「保存」のダイアログ: Markdown・HTML・PDF・DOCX・スライド・**PPTX** の順。会話の書き出しのダイアログには出さない。
- 説明は「PowerPoint で編集できるスライドで保存する（`---` か見出しで 1 枚ずつ分ける）」。アイコンは lucide の `GalleryHorizontal`（HTML スライドは `Presentation`）。

## ファイル構成

```
front/src/
├── constants/chat/pptx.ts               # スライドの寸法・行の間隔・セルの余白（割り付けと pptxgenjs の図形で共有）
├── lib/chat/document-model.ts           # markdownToBlocks に「コメントだけの生の HTML を出さない」指定を足す（判定は report-html の isCommentOnly を共有）
├── lib/chat/pptx-layout.ts              # 中間の形のスライドの割り付け（純関数。図形の位置・大きさ・続きのスライド・高さの見積もり）
├── lib/chat/report-pptx.ts              # 割り付け → pptxgenjs の図形（pptxgenjs を引数で受ける）・スライドマスター
├── hooks/chat/useReportExport.ts        # 形式に pptx を足す（図の PNG・import('pptxgenjs')・保存）
└── components/features/chat/organisms/ExportDialog.tsx  # 応答 1 件に PPTX の形式を足す
```

- `DocBlock` の種類を `splitSlides` の種類にする関数は `pptx-layout.ts` に置く（HTML スライドの `kindOfHast` と対）。

## やらないこと

- 会話全体の PPTX
- PowerPoint のテンプレート（スライドマスター）の選択・カスタマイズ
- 発表者のノート（Marp のコメントの書き方も含む）・切り替えの動き
- コードの色付け・添付画像
- フォントの実測による割り付け（見積もりで分ける）
