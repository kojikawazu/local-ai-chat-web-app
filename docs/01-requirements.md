## プロジェクト概要

ローカルLLM（Ollama）と対話できるチャットWebアプリケーション。
Nordic Frostデザインシステムをベースとした画面設計を採用する。

## 技術スタック

| 項目 | 技術 |
|------|------|
| フレームワーク | Next.js 16 (App Router) |
| 言語 | TypeScript 5 |
| React | React 19（React Compiler有効） |
| スタイリング | TailwindCSS 4 |
| アイコン | lucide-react |
| Markdown表示 | react-markdown + remark-gfm + rehype-highlight + mermaid（PlantUML は PlantUML サーバー） |

| LLMバックエンド | Ollama |
| LLMモデル | qwen3.8:27b（動的にモデル切替可能） |
| DB | PostgreSQL 16（Docker Compose） |
| ORM | Prisma 7 |
| E2Eテスト | Playwright |
| リンター | ESLint 9 |
| フォーマッター | Prettier |

## 機能要件

### 必須機能（MVP）

1. **チャット機能**
   - ユーザーがメッセージを入力し、Ollamaからの回答を受け取る
   - ストリーミングレスポンス対応（リアルタイムに1文字ずつ表示）
   - メッセージの送信（Enter / 送信ボタン）
   - Shift+Enterで改行
   - IME入力対応（日本語入力中のEnter確定で送信されない）

2. **画面構成**（`base/`のデザインを踏襲）
   - サイドバー：会話一覧、新規会話作成、設定ボタン（モバイル幅 768px 未満ではヘッダーのメニューボタンから開くドロワーで同じ操作を提供する）
   - ヘッダー：モデル選択ドロップダウン、メニューボタン（モバイル幅のみ）
   - チャットエリア：メッセージ一覧、自動スクロール
   - 入力エリア：テキスト入力、送信ボタン
   - フッター：システム情報

3. **Ollama連携**
   - Next.js Route Handlers経由でOllama APIと通信
   - ストリーミング（Server-Sent Events / ReadableStream）対応
   - 接続先は環境変数で設定可能（ローカルのみ想定）
   - 利用可能モデル一覧の動的取得

4. **会話履歴の永続化**
   - PostgreSQLに会話・メッセージを保存
   - 会話単位でグループ化し、サイドバーに一覧表示
   - 会話の新規作成・選択・切り替え
   - 応答の生成中に別の会話へ切り替えても生成は続き、応答は送信した会話に保存される。戻ると途中までの応答と続きが表示される。生成中の会話はサイドバーに印を付ける。生成中の状態・エラーは会話ごとで、切り替え先の会話の入力・表示には影響しない（#147）
   - 保存に失敗したメッセージは成功扱いにせず、画面上で失敗を明示して再試行できる（ユーザーメッセージの保存に失敗した場合は LLM に送らない）

### 追加機能

5. **モデル選択**
   - Ollamaの利用可能モデル一覧をAPI経由で取得
   - ヘッダーのドロップダウンからモデルを切り替え
   - 設定画面からもモデル変更可能

6. **設定画面**
   - モーダルダイアログで設定を表示
   - モデル選択
   - テーマ切替

7. **マークダウン表示**
   - AIレスポンスのMarkdownをリッチに整形表示
   - コードブロックはコードフェンスに書いた言語で色付けし（シンタックスハイライト）、右上に言語名を表示する。色はテーマに追従する
     - 言語の指定が無いブロックは自動判定せず単色で表示し、言語名も出さない。highlight.js に無い言語は色付けせず、言語名は出す
   - ` ```mermaid ` のブロックは図として表示する（#169）。色はテーマに追従する
     - 応答の生成中はソースのまま表示し、生成が終わってから図にする。描けないときはソースを表示し、描けなかったことを添える
   - ` ```plantuml ` / ` ```puml ` のブロックも図として表示する（#171）。ローカルの PlantUML サーバー（Docker）で描き、PlantUML の既定の見た目（白い地）のままにする（テーマには追従しない）
     - 外部の URL・ファイルの読み込み（`!include https://…` 等）は描かずにエラーにする。PlantUML サーバーに繋がらないときはソースを表示し、起動の手順を添える
   - テーブル、リスト、引用、リンク等のサポート
   - react-markdown + remark-gfm + rehype-highlight + mermaid を使用（詳細は [11-syntax-highlight-diagrams.md](./11-syntax-highlight-diagrams.md)）

8. **会話タイトル自動生成**
   - 新規会話の最初のメッセージ送信後、LLMでタイトルを自動生成
   - 日本語で20文字以内の簡潔なタイトル
   - サイドバーの会話一覧に反映

9. **テーマ切替**
   - 3種類のテーマを用意
     - Nordic Frost（デフォルト）：北欧ブルー
     - Aurora Borealis：紫とシアンのオーロラ
     - Midnight Ocean：深海ブルーのダーク
   - CSS変数ベースのテーマシステム（`data-theme`属性で切替）
   - localStorageに選択テーマを永続化
   - 設定画面から切替可能

10. **エージェント機能（ツール呼び出し）**
   - エージェントモード ON/OFF トグル（設定モーダル）、localStorage 永続化
   - 利用可能ツール: get_current_datetime, calculate, web_search, url_fetch
   - ツール実行中インジケーター表示（ToolCallIndicator）
   - ツール実行結果の折りたたみ表示（ToolCallResult）
   - Web 検索結果のリッチ表示（リンク付き）
   - 思考過程の表示（AgentThinking — 本文中の `<think>` タグ、または Ollama の `message.thinking` で思考過程を返すモデルで動作）
   - 通常チャット（エージェントモード OFF）では思考させず、最初の文字が出るまでの時間を優先する
   - システムプロンプトプリセット選択（リサーチャー / 分析者 / 比較レビュアー / なし）
   - 実行統計表示（ラウンド数・所要時間）

11. **コピー機能**
   - AI 応答全体のコピー（Markdown の原文をコピーする）
   - コードブロック個別のコピー（コードの中身のみ。右上のボタンは常に表示）
   - コピー結果の一時表示（成功: Check アイコン＋「コピーしました」、失敗: 警告アイコン＋「コピーに失敗しました」。2 秒後に戻る）
   - Clipboard API が使えない非 secure context（スマホから LAN の http アドレスで開いた場合など）では `execCommand('copy')` で代わりにコピーする

12. **生成の停止**
   - 応答の生成中は送信ボタンが停止ボタンに替わり、押すと生成を止める。入力欄での Escape でも止められる（IME の変換中は除く）。止まるのは表示中の会話の生成だけ
   - 生成中の会話を削除すると、その生成を止め、応答を保存しない
   - 止めた時点までの本文を「生成を中断しました」の表示付きで残し、DB にも中断マーク（`metadata.interrupted`）付きで保存する。本文が 1 文字も届く前に止めた場合は応答を残さない
   - サーバーは停止を受けて Ollama への接続を切り、生成を止める。エージェントでは実行中のツールを中断し、次のラウンドへ進まない
   - SSRF 防止（DNS 解決後 IP ブロックリスト、redirect: 'error'）

13. **応答の再生成**
   - 最後の AI 応答の下に「再生成」ボタンを出し、同じ質問で応答を作り直す（途中の応答は後続のやり取りと食い違うため対象外）
   - 新しい応答は旧応答と同じ位置に表示し、生成し終えてから DB 上の旧応答を置き換える。生成に失敗した場合・本文が出る前に停止した場合は旧応答に戻し、DB は書き換えない
   - 生成中は再生成ボタンを押せない。保存に失敗している応答には出さない（先に再試行する）
   - 置き換えの保存に失敗した場合は、通常の保存失敗と同じく失敗表示と再試行ボタンを出す

14. **会話の役割（システムプロンプト）**
   - 会話ごとに AI の役割（システムプロンプト）を設定できる。DB の会話に保存し、開き直しても戻る
   - ヘッダーに現在の役割（プリセット名・「カスタム」・「役割なし」）を表示し、押すと編集ダイアログを開く
   - プリセット（翻訳者・コードレビュアー・日本語教師）を選ぶと本文が入り、そのまま書き換えてもよい。空にすると役割を外す。上限は 5,000 文字
   - 会話を作る前に選んだ役割は、最初の送信で会話と同時に保存する。新しい会話は役割なしで始まる
   - 途中で変えた役割は以降の送信から効き、これまでの応答はそのまま残る
   - エージェントモードでは、会話の役割の後ろにエージェントのプリセットを連結して送る

15. **会話検索**
   - サイドバーの検索欄にキーワードを入れると、会話のタイトルとメッセージの本文（質問・応答）から会話を探す（#11）
   - 空白で区切った語は、すべてを含む会話を探す（AND。5 語・100 文字まで）。大文字・小文字は区別しない
   - 結果にはタイトルと、最初に一致したメッセージの一致箇所の前後を出し、キーワードを強調する。押すとその会話を開く
   - 更新日時の新しい順に 20 件ずつ出し、続きは「さらに表示」で読む
   - × ボタン・Escape で検索をやめ、履歴一覧に戻る

16. **書き出し（エクスポート）**
   - AI 応答の下の「Markdown で保存」で、その応答の本文（Markdown の原文。「コピー」と同じ中身）を `.md` ファイルとして保存する（#12）
   - ヘッダーの「会話を書き出す」で、表示中の会話全体を保存する。形式はダイアログで選ぶ
     - Markdown: タイトル・書き出した日時・会話の役割と、質問・応答を「## ユーザー（日時）」「## アシスタント（日時）」の見出しで `---` 区切りに並べる。思考過程・ツールの結果は入れない。中断した応答にはその旨を添える
     - JSON: バックアップ用に、会話（ID・タイトル・役割・日時）とメッセージ（metadata を含む）を省かずに出す（`version: 1`）。読み込み（復元）は無い
   - ファイル名は `<会話のタイトル>_<YYYY-MM-DD_HHmm>.<md|json>`（ローカル時刻。応答 1 件は応答の作成日時）。ファイル名に使えない文字・制御文字は `_` に置き換え、タイトルは 50 文字まで。空なら「会話」
   - 会話を開く前（新しい会話）と応答の生成中は、会話全体の書き出しを押せない
   - 保存はブラウザの中で行い（`Blob` と `<a download>`）、サーバーを経由しない

## 非機能要件

- ローカル環境で動作すること
- レスポンシブデザイン対応（base/のデザインに準拠）。320px 以上の幅で、デスクトップにある会話管理（選択・新規作成・削除）と設定の操作が欠けないこと。モバイルのドロワーはキーボード操作（Escape で閉じる・フォーカストラップ・閉じた後のフォーカス復帰）と支援技術向けの状態表示（`aria-expanded` / `aria-modal`）に対応する
- PostgreSQLはDocker Composeで管理
- **CI/CD**: GitHub Actionsで E2E テストを自動実行（push/PR to main）
- **ドキュメント**: macOS向けセットアップガイドを提供（`manuals/setup-guide-macos.md`）

## セキュリティ要件

- **認証**: 不要（localhost個人利用）
- **公開範囲**: localhost限定
- **入力バリデーション**: 厳格（XSS防止、CSPヘッダー設定、入力パターン検証）
- **メッセージ最大文字数**: 10,000文字（フロントエンド + API両方でチェック）。AI応答の保存上限は100,000文字（API でチェック）
- **Rate Limiting**: 不要
- **エラー情報**: 詳細をクライアントに返す（ローカル利用のため許容）
- **`dangerouslySetInnerHTML` 使用禁止**
- 詳細は `docs/05-security.md` を参照
