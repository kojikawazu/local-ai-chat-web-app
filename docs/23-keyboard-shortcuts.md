# ショートカットキー 設計書

> 最終更新: 2026-10-31

マウスを使わずに主な操作（新しい会話・会話の検索・サイドバーの開閉・入力欄へのフォーカス・会話の切り替え）をできるようにし、ショートカットの一覧をヘルプで見られるようにするための設計（#33 の Phase A〜C。サブ issue #217）。ショートカットのカスタマイズは含めない。

## 背景

会話を行き来しながら使うと、新しい会話・検索・サイドバーの開閉のたびにマウスへ手を移すことになる。入力欄に打っている途中で別の会話を見たいときも同じ。よく使う操作をキーで呼べれば、キーボードから手を離さずに続けられる。

## 今あるキー操作

| 場所 | キー | 動き |
|---|---|---|
| 入力欄 | Enter / Shift+Enter | 送信 / 改行（IME の変換中は送信しない） |
| 入力欄 | Escape | 生成中なら止める（テンプレートの候補が出ていれば、先に候補を閉じる） |
| 入力欄 | 先頭の `/` | プロンプトテンプレートの候補（#28） |
| 検索欄 | Escape | 入力を消す |
| モーダル（`<dialog>`） | Escape | 閉じる（ブラウザの標準の動き） |
| ドロワー | Escape | 閉じる |

ページ全体で受けるショートカットはまだ無い。新しく足すショートカットは、これらと重ならないようにする。入力欄・検索欄の Escape（生成を止める・候補を閉じる・入力を消す）は、Shift+Escape のときは動かさない（入力欄へのフォーカスに使うため）。

## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| ページ全体のショートカット（新しい会話・検索・サイドバー・入力欄・前後の会話・ヘルプ） | ショートカットのカスタマイズ（issue の Phase C の「将来拡張」） |
| サイドバーの会話一覧の ↑↓・Home・End での移動（Enter で開くのはボタンの標準の動き） | 応答のコピー・再生成・分岐などの、応答ごとの操作のキー |
| ショートカットの一覧のヘルプ（キーと、設定モーダルのボタンから開く） | `/` で入力欄にフォーカス（[論点](#決めることレビューの論点)） |

## 決めること（レビューの論点）

| 論点 | 推奨 | 他の案 | 理由 |
|---|---|---|---|
| 新しい会話のキー | **⌘⇧O（Mac）/ Ctrl+Shift+O** | issue の案の ⌘N / Ctrl+N | ⌘N・Ctrl+N はブラウザが「新しいウィンドウ」に使い、ページから止められない（`preventDefault` が効かない）。⌘⇧O は Chrome（E2E のブラウザ）でページに渡ることを E2E で確かめる。Firefox ではブックマークの管理に割り当てがあるため、効かなければヘルプに注記する |
| 入力欄へのフォーカス | **Shift+Escape** | issue の案の `/`・Escape | `/` は入力欄の外で押すと、入力欄に移ったあと、テンプレートの候補を出すにはもう一度 `/` が要って紛らわしい。Escape だけは、入力欄で生成を止める・検索欄を消す・モーダルを閉じるに使っている |
| 前・次の会話 | **Ctrl+Shift+↑ / ↓**（Mac でも Ctrl） | ⌘⇧↑↓・⌥↑↓ | Mac の入力欄では ⌘⇧↑↓（先頭・末尾まで選ぶ）と ⌥↑↓（段落の移動）がテキストの編集に使われる。Ctrl+Shift+↑↓ は Mac のテキストの編集に使われず、既定の設定の Mission Control（Ctrl+↑↓。Shift なし）とも別のキー |
| 前・次の会話の端 | **止まる**（一番上で ↑・一番下で ↓ を押しても動かない）。新しい会話のモードでは ↓ で一番上の会話へ | 端で反対側へ回る | 会話の一覧は新しい順に長く並ぶ。回ると、一番古い会話へ飛んでどこにいるか分からなくなる |
| 入力欄の中でも効かせるか | **修飾キー付きのもの（⌘・Ctrl・Shift+Escape）は効かせる。** `?` だけは入力欄の外でしか効かせない | すべて入力欄の外だけ | 打っている途中で別の会話を見たいときに、入力欄から出ずに使えるようにする。修飾キー付きのものは、入力欄の文字の入力・編集と重ならない |
| ヘルプのキー | **⌘/ / Ctrl+/** と、入力欄の外の `?` | `?` だけ | 入力欄の中では `?` を打つので、修飾キー付きのものも用意する |
| ヘルプの見せ方 | **共通の `Modal` のダイアログ**。設定モーダルの「キーボードショートカット」のボタンからも開く | ツールチップ・フッターに常に出す | キーを知らない人の入口が要る。一覧が 8 行ほどあり、ツールチップには収まらない |
| キーの表記 | **Mac は ⌘ ⇧ ⌃、それ以外は Ctrl・Shift** を、開いている端末で出し分ける | どちらも並べて書く | 自分の端末の表記だけの方が読みやすい |
| サイドバーの一覧の移動 | **入れる**（会話の行にフォーカスがあるとき ↑↓・Home・End で行を移る。Enter で開くのはボタンの標準） | 入れない（Tab だけ） | 会話が多いと Tab では削除のボタンも挟まり、移るのに 2 倍押すことになる |
| モバイルの幅（md 未満） | **サイドバーの開閉・検索はドロワーを開く**（検索は欄にフォーカスまで） | モバイルでは効かせない | 外付けのキーボードを使う人もいる。サイドバーの代わりがドロワーなので、同じ意味で動かす |
| カスタマイズ | **入れない** | issue の Phase C | キーの数が少なく、入れ替えたい場面がまだ無い。使ってから決める |

## ショートカットの一覧

| 操作 | Mac | Windows / Linux | 入力欄の中 |
|---|---|---|---|
| 新しい会話 | ⌘⇧O | Ctrl+Shift+O | 効く |
| 会話を検索（検索欄にフォーカス） | ⌘K | Ctrl+K | 効く |
| サイドバーを開く・閉じる | ⌘B | Ctrl+B | 効く |
| 入力欄にフォーカス | ⇧Esc | Shift+Esc | 効く（もう入力欄なら何もしない） |
| 前の会話 / 次の会話 | ⌃⇧↑ / ⌃⇧↓ | Ctrl+Shift+↑ / ↓ | 効く |
| ショートカットの一覧 | ⌘/ または ? | Ctrl+/ または ? | ⌘/・Ctrl+/ だけ効く |
| （サイドバーの一覧）前・次・最初・最後の会話へ | ↑ / ↓ / Home / End | 同じ | 会話の行にフォーカスがあるときだけ |

- キーの定義（操作・キー・入力欄の中で効くか・ヘルプの説明）は 1 か所（`constants/shortcut/shortcuts.ts`）に置き、判定とヘルプの両方がそれを読む（片方だけ直して食い違わないようにする）。
- キーは `event.key` で判定する（`O`・`K` は大文字・小文字の両方を受ける）。修飾キーは**ちょうど一致**するときだけ受ける（⌘K のつもりで ⌘⇧K を押しても、⌘⇧K には何も割り当てない）。
- ショートカットとして受けたら `preventDefault` する（ブラウザの既定の動き（⌘K の検索欄・⌘B のブックマーク等）を止める）。

## 効かせない場面

次のときは、ページ全体のショートカットを受けない（キーをそのままにする）。

| 場面 | 理由 |
|---|---|
| IME の変換中（`isComposing`） | 変換の確定・候補の選択のキーと重なる |
| モーダル（`<dialog open>`）・ドロワーが開いている | 背景の画面の会話を切り替えると、開いているダイアログと中身が食い違う。モーダルの中のキーはモーダルに任せる |
| ほかの部品がもう処理した（`defaultPrevented`） | 入力欄のテンプレートの候補の ↑↓・Enter など |
| キーを押しっぱなし（`repeat`）。ただし前・次の会話は除く | 新しい会話・サイドバーの開閉が連続で走らないようにする。会話の切り替えは押しっぱなしで続けて移れる方が便利 |
| `?` を入力欄・検索欄・テキストの欄（`input`・`textarea`・`select`・`contenteditable`）で押した | 文字として打つため |

- 生成中でも効かせる（新しい会話・別の会話へ移っても、生成は裏で続く。#147 の会話ごとの状態のまま）。
- 操作の関数は最新の状態のものを使う（`useKeyboardShortcuts` は関数を ref に持ち、`useLayoutEffect` で描画の直後に入れ替える）。`useEffect` で入れ替えると、会話を選んだ直後に押したキーが、選ぶ前の状態の関数で動く（E2E で見つけた）。

## サイドバーの会話一覧の移動

- 会話の行（`ConversationListItem` の行のボタン）にフォーカスがあるとき、↑↓ で前・次の行、Home・End で最初・最後の行へフォーカスを移す。端では止まる。
- 移すのはフォーカスだけで、会話は開かない（Enter・Space で開くのはボタンの標準の動き）。
- 削除のボタンは対象にしない（行から行へ移る）。
- 検索の結果（`SearchResultItem`）の一覧も同じ動きにする。

## ヘルプ

- ⌘/・Ctrl+/、入力欄の外の `?`、設定モーダルの「キーボードショートカット」のボタンで開く。もう開いていれば何もしない。
- 中身は [ショートカットの一覧](#ショートカットの一覧) の表と同じ（定義から作る）。キーは `<kbd>` で、開いている端末の表記で出す。
- 閉じたら、開く前にフォーカスがあった所に戻す（ネイティブの `<dialog>` の標準の動き）。

## ファイル構成

```
front/src/
├── constants/shortcut/shortcuts.ts                # ショートカットの定義（操作・キー・入力欄の中で効くか・説明）
├── lib/shortcut/match.ts                           # キーの判定（定義との一致・効かせない場面・端末の表記）。純ロジック
├── lib/sidebar/list-navigation.ts                  # 一覧の ↑↓・Home・End の移る先（端で止まる）。純ロジック
├── hooks/shortcut/useKeyboardShortcuts.ts          # document の keydown を受け、操作ごとの関数を呼ぶ
├── components/features/shortcut/organisms/ShortcutHelpDialog.tsx  # ショートカットの一覧のダイアログ
├── components/features/sidebar/organisms/SidebarContent.tsx       # 一覧の ↑↓ の移動・検索欄へのフォーカス
├── components/features/sidebar/organisms/ConversationSearch.tsx   # 検索欄にフォーカスさせる口
├── components/features/settings/organisms/SettingsModal.tsx       # 「キーボードショートカット」のボタン
└── app/page.tsx                                    # フックを呼び、操作（新しい会話・会話の切り替え等）を繋ぐ
```

- 機能 `shortcut` を足すため、`eslint.config.mjs` の `UI_FEATURES` に足す。
- 「前・次の会話」の移る先も `list-navigation.ts` で決める（サイドバーの並び＝会話一覧の並び）。

## テスト

| 層 | 対象 |
|---|---|
| UT（`keyboard-shortcuts.test.ts`） | キーの判定（Mac は ⌘・それ以外は Ctrl・大文字小文字・修飾キーのちょうど一致・⌘⇧K を ⌘K と見ない）・効かせない場面（IME・モーダル・`defaultPrevented`・`repeat`（前・次の会話は通す）・入力欄の `?`）・端末の表記・一覧の移る先（↑↓・Home・End・端で止まる・現在が無いとき・空の一覧） |
| IT | 対象なし（API・DB を変えない） |
| E2E（`keyboard-shortcuts.spec.ts`） | 各ショートカット（新しい会話・検索欄にフォーカス・サイドバーの開閉・入力欄にフォーカス・前後の会話・ヘルプ）・入力欄の中でも効く・入力欄の `?` は文字になる・モーダルが開いている間は効かない・サイドバーの一覧の ↑↓・Home・End・端で止まる・設定モーダルからヘルプを開く。会話は API で作る（Ollama を使わない）ため、軽量モデル・CI でも動く。IME の変換中はブラウザで安定して起こせないため UT で見る。⌘ と Ctrl は、アプリが判定した端末から選ぶ（`devices['Desktop Chrome']` は User-Agent を Windows にするため、Playwright の `ControlOrMeta` とは食い違う） |

## やらないこと

- ショートカットのカスタマイズ（使ってから決める）
- 応答ごとの操作（コピー・再生成・分岐・ブックマーク）のキー
- `/` で入力欄にフォーカス（Shift+Escape で代える）
- 承認カードの許可・拒否のキー（押し間違いで実行させないため、マウス・Tab で選ばせる）
