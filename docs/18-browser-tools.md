## 背景

今の Web のツールは `web_search`（検索結果）と `url_fetch`（HTML の本文）だけで、静的に取れる内容しか読めない。

- JavaScript で描画するページ（SPA）の内容が読めない。
- 画面の見た目を確かめられない。開発中のアプリの動作確認（#148 のツールでコードを直した後に画面を見る）に使いたい。
- `url_fetch` はプライベートの IP アドレス（`localhost` 等）を止めているため、手元の開発サーバーを読めない。

## 前提の調査

Playwright 1.64.1（E2E で使っている版）と `qwen3.8:27b`（Ollama 0.40.5）で確かめた（2026-10-30）。

### スナップショットの大きさ

ビューポート 1280×800 で、`domcontentloaded` の後に取った。

| ページ | 取得の時間 | スナップショット（通常） | スナップショット（`mode: 'ai'`。要素の参照付き） | スクリーンショット（PNG） |
|---|---|---|---|---|
| example.com | 0.8 秒 | 1,047 文字 | 1,176 文字 | 81 KB |
| nextjs.org/docs | 1.4 秒 | 13,975 文字 | 21,732 文字 | 138 KB |
| GitHub のリポジトリのトップ | 1.9 秒 | 25,581 文字 | 41,626 文字 | 92 KB |
| ja.wikipedia.org の記事 | 0.9 秒 | 39,749 文字 | 63,220 文字 | 250 KB |

- 文書の多いページは、そのまま渡すと数万文字になる。入力を読む速さ（1 秒あたり 100〜130 トークン。[14-local-file-tools.md](./14-local-file-tools.md)「前提の調査」）から、上限が要る。
- `mode: 'ai'` は要素ごとに `[ref=e13]` の参照を付け、`aria-ref=e13` でその要素を指せる（クリックで確かめた）。操作（Phase C）の要素の指定に使えるが、文字数が 1.5 倍になる。

### ツールの結果に画像を付ける

`role: 'tool'` のメッセージに `images`（base64）を付けて、合言葉とボタンの文字を書いたページ（1280×800）のスクリーンショットを渡した。

| 渡し方 | 入力のトークン | 答え |
|---|---|---|
| 画像を付ける | 1,329 | 合言葉「ペンギン42」・ボタン「送信する」を正しく読んだ（20 秒） |
| 文章だけ（「スクリーンショットを撮りました」） | 326 | **画面に無い「グレーの円」「Open in new window」を作って答えた** |

- ツールの結果の画像は読める。1280×800 で約 1,000 トークン増える。
- 画像を渡せないのに「撮った」とだけ返すと、モデルは見たふりをする。画像を読めないモデルには、スクリーンショットのツールを渡さない（[スクリーンショットをモデルへ渡す](#スクリーンショットをモデルへ渡す)）。

### リダイレクトの先の判定

許可したポート A・C と、止めたいポート B の 3 つのサーバーを手元に立て、A→B・A→C→B と転送させた。

| 判定のしかた | A→B | A→C→B | ページの中から B への `fetch` |
|---|---|---|---|
| `context.route` で横取りし、通すものは `route.continue()` | **B が読めた** | — | — |
| `route.fetch({ maxRedirects: 0 })` で取り、転送の先を確かめてから `route.fulfill` | 止まった | **B が読めた** | — |
| アプリの中のプロキシにすべての通信を通す（`launch({ proxy })`） | 止まった | 止まった | 止まった |

- `route` は転送の 2 回目以降を通らない。302 を返すとブラウザが自分で先へ進むため、連鎖をすべて確かめられない。
- プロキシなら、転送の先・ページの中のリクエスト・HTTPS（`CONNECT`。暗号は解かず宛先だけを見る）がすべて新しい接続としてプロキシに来る。Chromium は既定でループバックへの通信をプロキシに通さないため、`bypass: '<-loopback>'` で外す（`localhost` もプロキシに来ることを確かめた）。

### Next.js からの読み込み

`playwright-core` は Next.js 16 の `serverExternalPackages` の既定の一覧に入っている。`next.config.ts` を変えずに、Route Handler から読み込める（バンドルされない）。

## 決めること（レビューの論点）

| 論点 | 推奨 | 他の案 | 理由 |
|---|---|---|---|
| 最初のサブ issue の範囲 | **基盤と読み取り（Phase A・B）だけ**。操作（Phase C）は別のサブ issue | 操作まで一度に入れる | #148 と同じく、リスクの低い読み取りから入れて使い方を見る。操作は承認が要り、要素の指定（参照）の作りも別に決める |
| ライブラリ | **`playwright-core`** を `dependencies` に足す（`@playwright/test` と同じ版） | `@playwright/test` を本番のコードから読み込む・別のライブラリ（Puppeteer 等） | E2E で使い慣れていて、Chromium も `pnpm exec playwright install chromium` で入る。`@playwright/test` は開発用の依存のため本番のコードから読まない。`playwright-core` はブラウザをダウンロードしない |
| 有効にする設定 | **`BROWSER_ENABLED=true`** で登録する（既定は使わない）。手元の開発サーバーは **`BROWSER_LOCAL_ORIGINS`** に書いたオリジンだけを開ける | 既定で有効（`url_fetch` と同じ）／`BROWSER_ALLOWED_ORIGINS` で公開の Web も含めて許可リストにする | ブラウザは Chromium のインストールとメモリ（数百 MB）が要るため、利用者が選んで使う。公開の Web まで許可リストにすると、SPA を読む使い方がほぼできない。手元のサービス（DB の管理画面・Ollama 等）は明示したものだけを開ける |
| セッションの長さ | **1 回の応答の間だけ**。応答が終わったらページを閉じる | 会話ごとに持ち、一定時間で閉じる | 読み取りだけなら、続きは URL を開き直せば足りる。会話ごとに持つには `/api/chat` に会話 ID を渡し、放置の後始末を作る必要がある。ログインした状態を続ける操作（Phase C）で要るなら、そこで作る |
| 宛先の判定のしかた | **アプリの中のプロキシ**に Chromium の通信をすべて通し、接続ごとに判定する | Playwright の `route` で横取りする | `route` は転送の連鎖をすり抜ける（[前提の調査](#リダイレクトの先の判定)）。プロキシは名前を引いて確かめたアドレスへそのまま接続するため、DNS rebinding も防げる |
| ツールの分け方 | **3 つ**: `browser_navigate`（開いて、スナップショットを返す）・`browser_snapshot`（今のページを読み直す・続きを読む）・`browser_screenshot` | 開くだけのツールと読むツールを分ける | 開いたら読むのがほぼ毎回なので、1 回の呼び出しで済ませる（ラウンドが 1 つ減ると、モデルがそれまでの文脈を読み直す時間が減る） |
| スナップショットの形 | **通常の形**（参照なし）。操作を足すときに `mode: 'ai'` へ変える | 最初から `mode: 'ai'` | 読み取りでは参照を使わず、文字数が 1.5 倍になるだけ。上限の中で読める内容が減る |
| スナップショットの上限 | **12,000 文字**で切り、続きは `browser_snapshot` の `offset` で読む | 上限なし・要約する | `read_file` と同じ上限（約 4,000 トークン・読むのに 30 秒程度）。要約はモデルを 2 回呼ぶことになる |
| 画像を読めないモデル | **`browser_screenshot` をツールの一覧から外す** | 渡したうえで、呼ばれたら失敗を返す | 調査で、画像の無い結果に対してモデルは見たふりをした。渡さなければ呼べない |
| スクリーンショットの表示 | **モデルに渡すだけ**。画面には「撮った」記録（大きさ）だけを出す | 画面にも出す・DB に保存する | 添付画像（`Attachment`）は利用者のメッセージに付く形で、応答の画像の置き場が無い。表示は使ってみて要るなら足す |
| 手元のページを読んだ後 | **手元の開発サーバーのページは `local`**（手元の情報を読む）として扱う。公開の Web を開くのは `network` | ブラウザのツールはすべて `network` | 手元のアプリの画面には非公開の情報が出る。読んだ後に公開の URL を開かせると、URL に載せて外へ送れる（[外部への持ち出しとの関係](#外部への持ち出しとの関係)） |

## 有効にする設定

| 変数名 | 説明 | 既定 |
|---|---|---|
| `BROWSER_ENABLED` | `true` でブラウザのツールを登録する | 未設定（使わない） |
| `BROWSER_LOCAL_ORIGINS` | 開いてよい手元の開発サーバーのオリジン（`http://localhost:5173` の形。カンマ区切り） | 未設定（手元のサーバーは開けない） |

- `BROWSER_LOCAL_ORIGINS` はオリジン（スキーム・ホスト・ポート）で書く。パスが付いていたら警告して外す。`http`・`https` 以外は外す。ポートの省略は既定のポート（80・443）として扱う。
- **このアプリ自身のオリジンは、書いても開けない**（[脅威と対策](#脅威と対策)）。`/api/chat` のリクエストのオリジンを、応答ごとの文脈で渡す。文字列では比べず、**名前を引いたアドレスがループバックで、ポートがアプリと同じ**なら止める（`localhost`・`127.0.0.1`・`[::1]` の書き方の違いですり抜けさせない）。
- Chromium が入っていない（`pnpm exec playwright install chromium` をしていない）ときは、ツールは登録したまま、最初の呼び出しで「使えない」（`toolUnavailable`）を返し、入れ方を伝える。起動時に確かめると、使わないときも起動が遅くなるため。

## ツール

### `browser_navigate`

| 引数 | 必須 | 説明 |
|---|---|---|
| `url` | ✓ | 開く URL（`http`・`https`） |

- [開いてよい URL](#開いてよい-url) で確かめてから開く。`waitUntil: 'load'` で待ち、続けてネットワークが落ち着くのを最大 2 秒待つ（SPA の描画を待つため。落ち着かなくても先へ進む）。
- 結果: 最後の URL（リダイレクトの後）・タイトル・HTTP の状態・スナップショット（先頭から 12,000 文字）。切ったときは、全体の文字数と、続きを `browser_snapshot` の `offset` で読めることを書き添える。
- 要約（画面の 1 行）: `タイトル（ホスト）`。
- HTTP の状態が 4xx・5xx でも、ページが返れば成功として本文を返す（エラーのページの内容がモデルの判断に要るため）。状態は結果に書く。

### `browser_snapshot`

| 引数 | 必須 | 説明 |
|---|---|---|
| `offset` | | 読み始める文字の位置（既定 0）。続きを読むときに使う |

- この応答で開いたページを読み直す（描画を待ってから読む・切った続きを読む）。開いていなければ失敗（「先に `browser_navigate` で開いてください」）。

### `browser_screenshot`

引数なし。今のページの見えている範囲（1280×800）を PNG で撮り、モデルへ画像として渡す（[スクリーンショットをモデルへ渡す](#スクリーンショットをモデルへ渡す)）。ページ全体（`fullPage`）は撮らない（縦に長いページはトークンが大きくなるため）。

## 開いてよい URL

開く URL と、ページが読み込むすべてのリクエスト（画像・スクリプト・`fetch`・リダイレクトの先）を、宛先ごとに判定する。

| 宛先 | 扱い |
|---|---|
| `http`・`https` 以外（`file:`・`data:`・`chrome:`・`javascript:` 等） | 止める（開く URL のとき。ページの中の `data:`・`blob:` の読み込みは止めない） |
| このアプリ自身のオリジン | 止める |
| `BROWSER_LOCAL_ORIGINS` のオリジン | 通す（`local`） |
| 名前を引いたアドレスがプライベート・ループバック・リンクローカル | 止める（`url_fetch` と同じ範囲。判定は `url-fetch.ts` から切り出して共通にする） |
| それ以外（公開の Web） | 通す（`network`） |

- **プロキシで判定する**: Chromium を `launch({ proxy: { server, bypass: '<-loopback>' } })` で起動し、すべての通信をアプリの中の小さい HTTP プロキシ（`127.0.0.1` の空きポート）に通す。プロキシは、`http` はリクエストの URL、`https`・WebSocket は `CONNECT` の宛先（ホスト・ポート）で判定する。HTTPS の中身は解かない。
- **確かめたアドレスへ接続する**: プロキシが名前を引き、引けたアドレスをすべて判定してから、そのアドレスの中から接続する（Chromium には名前を引かせない。接続には、判定したアドレスだけを返す `lookup` を渡す）。判定と接続のアドレスが同じため、DNS rebinding で判定をすり抜けられない。アドレスを 1 つに絞らないのは、`localhost` が `::1` → `127.0.0.1` の順に引け、`127.0.0.1` だけで待ち受ける開発サーバーに `::1` で断られるため（Node が順に試す）。
- 転送（リダイレクト）の先・ページの中のリクエストも、新しい接続としてプロキシに来るため、同じ判定を通る（[前提の調査](#リダイレクトの先の判定)）。
- 開く URL は、ブラウザに渡す前にも同じ判定をする（止める理由をはっきり返すため）。開く URL そのものを止めたときは、理由を結果に書く（「プライベートのアドレスのため開けません。手元の開発サーバーなら BROWSER_LOCAL_ORIGINS に書いてください」）。ページの中のリクエストを止めたときは、プロキシが 403 を返す。
- プロキシは中継するだけで、本文をためない（流したまま渡す）。
- IT で、許可したサーバー A から許可していないサーバー B への転送・A → 許可したサーバー C → B の連鎖・ページの中の B への `fetch`・WebSocket のどれでも、B に 1 度もリクエストが届かないことを確かめた（WebSocket も `CONNECT` でプロキシに来る）。

## ブラウザとセッション

- **ブラウザは 1 つ**: Chromium（ヘッドレス）を最初の呼び出しで起動し、プロセスの中で使い回す（`globalThis` に持つ。承認待ちと同じく、route ごとにモジュールが別に読み込まれても共有するため）。借り手がいなくなってから 5 分使われなければ閉じる。
- **セッションは応答ごと**: 応答の最初のブラウザのツールの呼び出しで、プロキシと、新しいコンテキスト（Cookie・ストレージを持たない）とページを 1 つ作る。プロキシはコンテキストごとに渡す（`newContext({ proxy })`）。判定の決まり（アプリ自身のポート・手元の情報を読んだか）が応答ごとに違うため。応答が終わる（完了・エラー・停止）と、コンテキストとプロキシを閉じて Chromium を返す。同じ応答で並んだ呼び出しは、作成中のセッションを共有する。
- 同時に開くセッションは 2 つまで。超えたら「使えない」ではなく、入力に関係ない一時的な失敗として返す（ほかの応答が終われば使える）。
- コンテキストの設定: ビューポート 1280×800、ロケール `ja-JP`、`acceptDownloads: false`、権限（位置情報・カメラ等）は与えない、`serviceWorkers: 'block'`。
- 新しいウィンドウ（`window.open`・`target="_blank"`）は開かせず閉じる。ダイアログ（`alert`・`confirm`）は閉じる。
- 停止・タイムアウト: ツールの `signal` で、開いている読み込みを止める（`page.goto` は signal を受けないため、中断されたらページを閉じる）。ツール全般の上限（`AGENT_TOOL_TIMEOUT_MS`、既定 30 秒）の中で、開く時間の上限は 15 秒にする。

## ツールへ渡す応答ごとの文脈

今のツールは引数と `signal` だけを受け取り、応答をまたいだ状態を持たない。ブラウザのツールは「この応答で開いたページ」を共有するため、エージェントループからツールへ、応答ごとの文脈を渡す。

```ts
type ToolContext = {
  /** このアプリ自身のオリジン（ブラウザで開かせない） */
  appOrigin?: string;
  /** 応答ごとに 1 つ作るものを置く場所（ブラウザのセッション） */
  scope: Map<string, unknown>;
  /** 応答の終わりに後始末を登録する（ブラウザのセッションを閉じる） */
  onDispose: (dispose: () => Promise<void>) => void;
  /** この応答で手元の情報を読むツールが成功したか（プロキシが公開の Web へ接続しないために読む） */
  hasReadLocal: () => boolean;
};
```

- `execute(args, signal, context)` と 3 つ目の引数にする。今のツールは受け取らなくてよい（引数を減らした関数として型が合う）。ループは必ず渡す。ループの外（テスト）から直接呼ぶときは省略でき、ブラウザのツールは失敗を返す。
- ループは、応答の終わり（`finally`）で `onDispose` に登録された後始末を呼ぶ。
- `/api/chat` は `request.nextUrl.origin` を `runAgentLoop` に渡す。

## 外部への持ち出しとの関係

今のループは、手元の情報を読むツール（`access: 'local'`）が成功した後は、外部と通信するツール（`access: 'network'`）を同じ応答の中で止める（[14-local-file-tools.md](./14-local-file-tools.md)「外部への持ち出しを止める」）。ブラウザのツールは、開く先で触れるものが変わるため、`access` を呼び出しごとに決める。

| ツール | 実行の前（止めるかの判定。`access`） | 実行の後（手元を読んだか。結果の `readLocal`） |
|---|---|---|
| `browser_navigate` | 開く URL が `BROWSER_LOCAL_ORIGINS` なら `local`、それ以外は `network` | 開いた後（転送の後）のページが `BROWSER_LOCAL_ORIGINS` なら true |
| `browser_snapshot`・`browser_screenshot` | 付けない（読むだけで外へ送らない） | 今のページが `BROWSER_LOCAL_ORIGINS` なら true |

- `Tool` の `access` に、引数から決める関数も書けるようにする（`ToolAccess | ((args) => ToolAccess | undefined)`。ループの `resolveAccess`）。
- 実行の前の `access` は開く URL だけで決まるため、読み直し・スクリーンショットのように URL を取らないツールでは決まらない。そのため、ループだけが読む `readLocal` を結果に足し、実行の後でも「手元の情報を読んだ」とループに知らせる。
- **公開のページから手元へは接続させない**: 最上位のページが手元の開発サーバーのときだけ、プロキシが手元への接続を通す（`gateByTopPage`）。公開のページの中のスクリプト・iframe・画像が手元の開発サーバーを読み、外へ送ったり、ページに書き出してモデルに読ませたりする経路を止める（開発サーバーは CORS をすべて許可していることが多い）。公開の URL から手元への転送も止まる。最上位のページは、`browser_navigate` で開く前（`prepareNavigation`）と、ページの中の移動（`framenavigated`）で切り替える。手元のページが公開の CDN を読むのは止めない。PR #197 の自動のセキュリティレビューの指摘で足した。
- 手元の開発サーバーのページを読んだ後は、`web_search`・`url_fetch`・公開の Web を開く `browser_navigate` を止める。手元のファイルを読んだ後に、手元の開発サーバーを開くのは止めない（外へ出ないため）。
- **プロキシも止める**: 手元の情報を読んだ後は、プロキシが公開の Web への接続を断る（`ToolContext` の `hasReadLocal`）。手元の開発サーバーから公開の URL へ転送される場合と、すでに開いている公開のページのスクリプトが外へ送る場合も止まる（実装の中で、ツールの判定だけでは届かない経路として足した）。

## スクリーンショットをモデルへ渡す

- ツールの結果に、ループだけが読む `images`（base64 の PNG）を足す（`ToolExecution`。画面・DB へは送らない）。ループは `role: 'tool'` のメッセージの `images` に入れて Ollama へ渡す。
- 結果の文章は「スクリーンショット（1280×800）を画像で渡しました。URL: …」。画面の記録も同じ文章を出す。
- **画像を読めないモデルには渡さない**: ループの最初に、モデルの対応機能（`supportsVision`。#6）を確かめ、対応していなければ `browser_screenshot` をツールの一覧から外す。ツールの定義に `requiresVision: true` を持たせる。
- 画像は同じ応答の中でだけ使う。次の応答で履歴を送るときは、ツールの結果を履歴に入れない今の作りのまま（画像も残らない）。

## 上限値

| 項目 | 値 | 理由 |
|---|---|---|
| スナップショットの 1 回の文字数 | 12,000 文字 | `read_file` と同じ（約 4,000 トークン・読むのに 30 秒程度） |
| ページを開く時間 | 15 秒 | `url_fetch` と同じ。ツール全般の上限（30 秒）の中に収める |
| 描画を待つ時間（ネットワークが落ち着くまで） | 2 秒 | SPA の初回の描画を待つ。落ち着かないページ（ポーリング等）で時間を使い切らない |
| ビューポート | 1280×800 | 画像で約 1,000 トークン（[前提の調査](#前提の調査)） |
| 同時に開くセッション | 2 | 開発機のメモリ（64GB で大きいモデル・Docker と同時に動く） |
| ブラウザを閉じるまでの放置 | 5 分 | 続けて頼むときに起動を待たせない。使わなければメモリを返す |

## 脅威と対策

| 脅威 | 対策 |
|---|---|
| ページの中のプロンプトインジェクション（「この URL を開け」等） | 読み取りだけのため、できることは別の URL を開くことに限られる。手元の情報を読んだ後は公開の Web を開かせない（[外部への持ち出しとの関係](#外部への持ち出しとの関係)）。会話の中の情報を URL に載せて送る経路は `url_fetch` と同じく残る |
| 手元のサービスを読ませる（SSRF。Ollama・PostgreSQL の管理画面・ルーターの設定画面） | プライベートのアドレスは、`BROWSER_LOCAL_ORIGINS` に書いたオリジンだけを開ける。リダイレクトの先・ページの中のリクエストも、プロキシで接続ごとに判定する |
| このアプリ自身を開かせる（会話の一覧の API を読む。Phase C では承認カードを押す） | このアプリのオリジンは、`BROWSER_LOCAL_ORIGINS` に書いても止める |
| `file:` で手元のファイルを読ませる | `http`・`https` 以外は開かせない。ファイルを読むのはローカルのファイルのツール（許可したフォルダ・秘匿ファイルの除外がある）に任せる |
| ダウンロードでファイルを置かせる | `acceptDownloads: false` |
| 利用者のログイン情報を使わせる | 毎回、空のコンテキストで開く（利用者のブラウザのプロファイル・Cookie を使わない） |
| DNS rebinding（判定の後にアドレスを差し替える） | プロキシが名前を引いて判定したアドレスへそのまま接続する（Chromium に名前を引かせない） |
| ほかのプロセスにプロキシを使わせる | `127.0.0.1` の空きポートだけで待ち受け、ブラウザと一緒に閉じる。使われても、通すのは公開の Web と許可したオリジンだけ（ブラウザのツールと同じ範囲） |
| メモリの枯渇 | 同時のセッションの上限、放置で閉じる。プロキシは本文をためない |

## ファイル構成

```
front/src/lib/agent/tools/browser/
├── config.ts        # BROWSER_ENABLED・BROWSER_LOCAL_ORIGINS の解釈
├── url-policy.ts    # 宛先の判定（スキーム・アプリ自身・許可したオリジン・プライベートのアドレス）
├── proxy.ts         # 宛先を判定して中継する HTTP プロキシ（http・CONNECT）
├── browser.ts       # Chromium の起動・使い回し・同時のセッションの上限・放置で閉じる（globalThis）
├── session.ts       # 応答ごとのプロキシ・コンテキスト・ページと後始末
├── snapshot.ts      # スナップショットの取得・切り詰め・結果の文章
├── navigate.ts      # browser_navigate
├── read-snapshot.ts # browser_snapshot
└── screenshot.ts    # browser_screenshot
front/src/lib/agent/tools/network-guard.ts  # プライベートのアドレスの判定（url-fetch.ts から切り出す）
```

- `types.ts`: `ToolContext`、`access` の関数、`requiresVision`、`ToolExecution` の `images` を足す。
- `agent.ts`: 文脈の作成と後始末、`access` の解決、画像を読めないモデルからのツールの除外、ツールの結果の画像。
- `registry.ts`: `BROWSER_ENABLED` のときだけ 3 つを登録する。
- `/api/chat`: `runAgentLoop` にアプリのオリジンを渡す。
- `constants/chat/toolLabels.ts`: 3 つのツールの表示名。
- `constants/agent/browser.ts`: 複数のファイルで使う値（ページの大きさ・スナップショットの上限・止めたことを知らせるヘッダー・文脈が無いときの理由）。
- 依存: `playwright-core`（`@playwright/test` と同じ版に揃える。片方だけ上げると、入れた Chromium と版が合わなくなる）。

## テスト

| 層 | 対象 |
|---|---|
| UT | `BROWSER_LOCAL_ORIGINS` の解釈（パス付き・スキーム違い・既定のポート）・宛先の判定（スキーム・アプリ自身・許可したオリジン・プライベートのアドレス。名前の解決は引数で差し替える）・スナップショットの切り詰めと `offset`・`access` の決め方 |
| IT | 実際の Chromium で、テストの中で起こした HTTP サーバー（`127.0.0.1` の空きポート。`BROWSER_LOCAL_ORIGINS` に書く）を開く。`/api/chat`（Ollama はスタブ）経由で: 開いてスナップショットを返す・JavaScript で描いた文字が読める・許可したオリジンから許可していないポートへのリダイレクトを止める（許可したオリジンを経由する連鎖も）・ページの中の別ポートへの `fetch`・WebSocket を止める・アプリ自身のオリジンを止める・`file:` を止める・`offset` で続きを読む・スクリーンショットの画像が Ollama へのツールのメッセージに入る・画像を読めないモデルには `browser_screenshot` を渡さない・手元のページを読んだ後に公開の URL を開くのを止める・応答の後にセッションが閉じる・`BROWSER_ENABLED` が無ければ登録しない |
| E2E | `GET /api/tools` に出る（CI でも動く）。大きいモデルで、手元の確認用のページ（合言葉を JavaScript で描く）を開かせて答えさせる・許可していない手元のサーバー（PostgreSQL の 5499）は ❌・名前を引けないホスト（`.invalid`）は ❌（`IS_LIGHT_MODEL` でスキップ）。`file:` の URL は、大きいモデルが呼ぶのを断った（2 回とも理由を説明して呼ばなかった）ため、E2E では確かめず IT に任せる |

- 公開の Web に触れるテストは置かない（CI の安定のため。公開の宛先の判定は UT で名前の解決を差し替えて確かめる）。
- IT の CI ジョブ（`integration-test.yml`）に `pnpm exec playwright install --with-deps chromium` を足す。ブラウザは手元で動かす実依存で、IT の mock の方針（真の外部 3rd-party のみ差し替える）に沿う。
- E2E の確認用のページは、Playwright の `webServer` に小さい静的なサーバー（`tests/e2e/fixtures/browser/`）を足して配る。そのオリジンを dev サーバーの `BROWSER_LOCAL_ORIGINS` に渡す（`local-files.spec.ts` と同じく、これ無しで起動した dev サーバーを再利用すると落ちる）。

## やらないこと

- **クリック・入力・選択・スクロール**: Phase C（別のサブ issue）。フォームの送信など影響の大きい操作の前に承認を挟む。要素の指定に `mode: 'ai'` の参照を使う。
- **会話をまたぐセッション・ログイン**: Phase C で、操作と合わせて要るか決める。
- **画面に出して動かす（headed）**: 動作を見たいとなれば環境変数で切り替える。
- **スクリーンショットの表示・保存**: 応答に画像を付ける置き場から作る必要があるため、要るとなれば別に検討する。
- **Chromium 以外のブラウザ**: E2E と同じ Chromium だけにする。
