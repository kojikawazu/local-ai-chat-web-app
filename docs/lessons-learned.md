## 2026-11-05 Ollama のストリームの途中のエラーを読まず、応答が黙って空になっていた

### 概要

エージェントの応答が、ツールも本文も無いまま終わることがあった。Ollama が HTTP 200 のままストリームの途中で返す `error` の行を、アプリが読んでいなかった。空の応答を再生成すると保存が 404 になり、届いた回答も失われた。

### 詳細

- 何が起きたか: `qwen3.8:27b` でサブエージェントに任せる依頼を送ると、22 回中 6 回、Ollama がツール呼び出しの XML を解釈できずに失敗した。画面にはエラーが出ず、空の応答が残った。その応答を再生成すると `PUT` が 404 になり、再試行もできず、読み直すと回答が消えた
- なぜ起きたか（根本原因）: Ollama は応答を始めた後の失敗を `{"error":"..."}` の行で返す。読み取りの処理は `message` と `done` だけを見ていて、この行を無視した。画面は本文の無い応答を保存しないのに表示には残し、再生成のボタンも出していたため、DB に無い応答の置き換えに進んだ。API に直接送る確認ではプリセットのシステムプロンプトを付けておらず、見つかるまでに時間がかかった
- 教訓 / 次からどうする: ストリームを読む処理は、成功の形だけでなく、外部が返す失敗の行まで確かめる。原因が「モデルの気まぐれ」に見えたら、推測せずアプリと外部の間に記録の中継を挟んで生の出力を見る。API で再現を試すときは、画面が実際に送る内容（システムプロンプト・履歴）と揃える。保存しないものは画面にも操作の入口を残さない
- 関連: #251、`.claude/rules/api.md`（ストリーミング）、`docs/09-agent-architecture.md`

## 2026-11-04 撮影スクリプトが例外の後も終了せず、確認しないまま約 16 分待たせた

### 概要

MCP の画面のスクショを撮る使い捨てのスクリプトが、開始直後の例外の後も終了しなかった。時間の上限が無く、原因を確かめないまま流し直したため、数分で済む作業に約 16 分かかり、利用者に待ち時間の確認をさせた。

### 詳細

- 何が起きたか: Playwright の使い捨てのスクリプトを 2 回流し、それぞれ 500 秒・480 秒待った後に、裏の実行へ回った。撮影は 1 枚も進まず、3 回目でようやく撮れた。アプリと PR #246 に問題は無かった
- なぜ起きたか（根本原因）: 会話一覧の API の応答（`{"conversations":[...]}`）を配列と決めつけて `.map` を呼び、例外になった。この処理はブラウザを閉じる `try/finally` の外にあり、ブラウザが開いたままで Node のプロセスが終了しなかった。長引いたのは確認の仕方のせいで、時間の上限が無く、1 回目は出力を `tail` に通してエラーが見えなかった。1 回目の後はアプリの正常を確かめただけで例外を見つけないまま 2 回目を流し、ログをファイルに書いたのに、終わるまで待つ形で実行して読まなかった
- 教訓 / 次からどうする: 使い捨てのスクリプトにも、最初にプロセス全体の時間の上限（`setTimeout` で `process.exit`）を付け、例外で必ず `process.exit(1)` する。リソースを開いた直後から `try/finally` に入れる。ブラウザを使うものは裏で流し、ログをファイルへ書いて 1 分以内に読む。止まったら、原因が分かるまで同じものを流し直さない。API の応答の形は、使う前に `curl` で 1 回見る
- 関連: PR #246、#208
