## 背景

エージェントモード（#16・`docs/09-agent-architecture.md`）は、1 つのモデルが 1 つの会話の中でツールを呼び続ける。調べものでは Web のページ・手元のファイルを何枚も読み、その本文がすべてメインの会話の文脈に積まれる。ローカルのモデルは文脈が長くなるほど遅く・不正確になり、元の質問を見失いやすい。

サブエージェントは、任された仕事だけを別の会話で行い、まとめた文章だけを返す。読んだ本文はサブエージェントの会話に閉じ、メインの文脈には残らない。手順（調べ方・出典の書き方）も、仕事ごとの専用のプロンプトで安定させられる。

## 前提の調査

2026-11-03 に、`qwen3.8:27b` へ委譲のツール（`delegate_to_agent`。`agent` は `researcher`・`documents`、`task` は任せる仕事）と `web_search`・`calculate` を渡し、会話の履歴なしで 5 つの頼み方を試した（`/api/chat` を通さず Ollama へ直接。1 回ずつ）。

| 頼み方 | モデルの動き |
|---|---|
| こんにちは | ツールを使わずに答えた |
| 12 * 37 は？ | `calculate` を直接呼んだ（委譲しない） |
| Rust と Go の非同期処理の違いを、最新の情報で比べて | `researcher` に委譲。観点（実行モデル・同期の仕組み・最新の動向・選び方）と「出典を添えて日本語で」を書いた |
| 私のメモから、コーヒーの好みを探して教えて | `documents` に委譲。探す観点と「見つからなければその旨を書く」を書いた |
| Next.js 16 の新機能と、React 19 の新機能をそれぞれ調べて、まとめて比較して | 1 回の応答で `researcher` への委譲を 2 つに分けた |

分かったこと:

- **任せるかの判断と、任せる仕事の書き方は十分**: 会話を見ないサブエージェントに渡しても分かる形で書いた。
- **委譲のツールがあると、調べものに `web_search` を直接呼ばなくなる**: 今のエージェントモードの動き（と所要時間）が変わる。→ 有効にするかを利用者が選べるようにする（[設定](#設定)）。
- **1 回の応答で複数の委譲が来る**: Ollama は手元の 1 つのため、並べず 1 つずつ実行する。
- **任せる仕事に古い年（「2025 年時点」）を書く**: モデルの知識の古さが仕事の文に入る。→ サブエージェントにも今の日時を必ず渡す（`withCurrentDate`。#154）。

## 範囲

| 含める（Phase A） | 含めない（後の Phase・[やらないこと](#やらないこと)） |
|---|---|
| 委譲のツール `delegate_to_agent`（エージェントモード・設定で有効にしたときだけ） | 実行中にサブエージェントの中の手順を逐次出す（Phase B） |
| コードで定義した 2 つのサブエージェント（Web の調べもの `researcher`・手元の読みもの `reader`） | 利用者がサブエージェントを作る・プロンプトとツールを変える画面（Phase C） |
| サブエージェントのループ（メインのループと、ツールの実行・止める規則・時間の上限を共通にする） | 承認が要るツール・ブラウザのツールをサブエージェントに持たせる |
| 登録したドキュメントを探すツール `search_documents`（`reader` だけが使う） | サブエージェントからさらに委譲する（2 段以上） |
| 委譲の記録（任せた仕事・中のツールの呼び出し・回答）の保存と、ツールの結果のパネルでの表示 | サブエージェントごとに別のモデルを使う |
| 設定の切り替え（「サブエージェントに任せる」） | 複数のサブエージェントを同時に動かす |

## 決めること（レビューの論点）

2026-11-03 のレビューで、4 つの論点（有効にする方法・顔ぶれ・進捗の表示・`search_documents`）を推奨どおりに決めた。ほかも推奨どおり。

| # | 論点 | 推奨 | 理由 |
|---|---|---|---|
| 1 | 形 | **委譲のツール `delegate_to_agent`** をメインのループがツールとして呼ぶ（issue の案のまま） | 任せるかをモデルが決められる（[前提の調査](#前提の調査)で妥当だった）。停止・時間の上限・記録・止める規則をツールの仕組みのまま使える。アプリが先に仕事を分ける形は、分け方をアプリが知らないと作れない |
| 2 | 有効にする方法 | **設定の切り替え「サブエージェントに任せる」**（既定はオフ。エージェントモードのときだけ効く。`localStorage` に保存し、`/api/chat` へ `enableSubAgents` で渡す） | 有効にすると調べものをすべて任せ、応答が遅くなる（サブエージェントの会話のぶん、モデルへの問い合わせが増える）。今のエージェントモードを使っている人の動きを変えない |
| 3 | 顔ぶれ | **`researcher`（Web）と `reader`（手元）の 2 つ**。中で使うツールが 1 つも登録されていないサブエージェントは選ばせない | 文脈を膨らませる「何枚も読む」仕事は、Web と手元の 2 種類。外部と通信するか・手元を読むかで分けると、[外部への持ち出し](#外部への持ち出し)の規則をサブエージェント単位で当てられる |
| 4 | 持たせるツール | **読むツールだけ**（承認が要るツール・ブラウザのツールは持たせない） | 承認カードを入れ子にすると「誰が何のために頼んだか」の見せ方が増える。書き込み・操作はメインが承認付きで行えばよい。ブラウザは応答ごとのページ・画面の画像の扱いが要る |
| 5 | 深さ | **1 段**（サブエージェントには委譲のツールを渡さない） | 手元の 1 台のモデルで入れ子にすると、待ち時間が掛け算で増える。issue の「2〜3 段」は、1 段で使ってから決める |
| 6 | 渡すもの | **サブエージェントのシステムプロンプト・今の日時・任せた仕事（`task`）だけ**。会話の履歴・会話の役割・添付画像は渡さない | 任せた仕事だけに集中させ、文脈を小さく保つ。[前提の調査](#前提の調査)で、モデルは会話を見なくても分かる仕事の文を書けた |
| 7 | 返すもの | **サブエージェントの最終回答の文章だけ**（8,000 字で切る）。中のツールの結果はメインへ渡さない | 読んだ本文をメインの文脈に入れないのが目的。中の手順は記録として画面に出す |
| 8 | 実行の順 | **1 つずつ**（ツールの `exclusive` に `sub-agent` の組を置く） | Ollama は手元の 1 つ。並べても速くならず、モデルの読み込み直しを招く。`exclusive` はブラウザのツール（#149 Phase C）で作った仕組み |
| 9 | 進捗の表示 | **Phase A は、実行中は「リサーチャーに任せています」と経過時間、終わったら結果のパネルの中に任せた仕事・中の手順・回答を出す**。中の手順の逐次表示は Phase B | 終わった後の表示は、保存した記録から作れる（会話を開き直しても同じ）。逐次の表示は、ストリームのイベントとクライアントの状態の組み立て（`useChat`）を広く触るため分ける |
| 10 | 登録したドキュメントを探すツール | **`search_documents` を Phase A で足し、`reader` だけに持たせる**（メインの一覧には出さない） | `docs/28-rag.md` で #26 に回したもの。メインには「ドキュメントを参照」の切り替えがあり、同じ働きを 2 つ見せると迷わせる |

## 委譲の流れ

```
ブラウザ → /api/chat（enableTools・enableSubAgents）
  → メインのループ（runAgentLoop）
      ├─ delegate_to_agent { agent: "researcher", task: "…" }   ← exclusive: sub-agent で 1 つずつ
      │    → サブエージェントのループ（runSubAgent）
      │         system: researcher のプロンプト + 今の日時
      │         user:   task
      │         ├─ web_search / url_fetch …（止める規則・時間の上限はメインと同じ）
      │         └─ 最終回答（文章）
      │    ← 結果: 最終回答（8,000 字まで）＋ 記録（任せた仕事・中のツール・ラウンド数・トークン数）
      └─ メインが結果を読んで最終回答
```

- サブエージェントは、メインと同じモデル（リクエストの `model`）を使う。
- 停止・切断（`request.signal`）と委譲の時間の上限は、ツールの signal を通してサブエージェントの Ollama への問い合わせと中のツールまで止める。
- サブエージェントの思考過程（`thinking`）は捨てる（記録にも残さない）。本文の途中経過もメインのストリームに流さない。

## サブエージェント

定義はコード（`lib/agent/sub-agents.ts`）に置く。利用者が変える画面は Phase C。

| 名前 | 表示名 | 使うツール（登録されているものだけ） | 触れるもの（`access`） |
|---|---|---|---|
| `researcher` | リサーチャー | `web_search`・`url_fetch`・`get_current_datetime`・`calculate` | `network` |
| `reader` | 手元の読み手 | `list_directory`・`search_files`・`read_file`（`LOCAL_FILE_ROOTS`）・`github_list`・`github_view`・`github_pr_diff`（`GITHUB_REPOS`）・`search_documents`・`get_current_datetime`・`calculate` | `local` |

- 定義の形: `{ name, label, description（委譲のツールの説明に入れる 1 行）, systemPrompt, toolNames, access }`。
- **使えるサブエージェント**: 定義の `toolNames` のうち、`get_current_datetime`・`calculate` 以外のツールが 1 つ以上登録されているもの（`reader` は、ファイル・GitHub・ドキュメントのどれかが要る）。`search_documents` は常に登録するため、`reader` は実際には常に使える。
- システムプロンプト（要旨）:
  - `researcher`: 任された仕事を Web で調べる。複数の出典を読み、出典の URL を添えて 2,000 字ほどにまとめる。分からないこと・食い違いはそのまま書く。
  - `reader`: 任された仕事を、手元のファイル・GitHub・登録したドキュメントから探して読む。見つけた場所（パス・リポジトリと番号・ドキュメントの名前）を添えてまとめる。見つからなければ、どこを探したかと「見つからなかった」と書く。
- 今の日時は、メインと同じ `withCurrentDate` でシステムプロンプトの後ろに足す。

## 委譲のツール

`delegate_to_agent`（`lib/agent/tools/sub-agent/delegate.ts`）

| 引数 | 型 | 説明 |
|---|---|---|
| `agent` | `string`（使えるサブエージェントの名前の `enum`） | 任せる相手 |
| `task` | `string`（4,000 字まで） | 任せる仕事。会話を見ない相手にも分かるよう、何をどこまで調べ、何を返してほしいかを書く |

- 説明（モデル向け）: 「ページ・ファイルを何枚も読む調べもの・読みものを、専用のサブエージェントに任せる。サブエージェントはこの会話を見ないため、task だけで分かるように書く。1 回の検索・計算で済むなら自分でツールを呼ぶ」に、使えるサブエージェントの 1 行の説明を並べる。
- `access` は引数の `agent` から決める関数（`researcher` → `network`、`reader` → `local`）。今のループの止める規則がそのまま当たる（[外部への持ち出し](#外部への持ち出し)）。
- `exclusive: 'sub-agent'`（1 つずつ実行）。
- 時間の上限はサブエージェントが自分で守る（150 秒でまとめ始め、300 秒で止めて記録を返す）。委譲のツールの実行の上限は、止まらなかったときの保険として 330 秒にする。今の `runTimeoutMs`（承認の後の実行だけに効く）とは別に、承認の要らないツールの実行に効く上限（`timeoutMs`）を `Tool` に足す。
- 結果（モデルへ返す文章）は、サブエージェントの最終回答。8,000 字を超えたら切り、切ったことを末尾に書く。Ollama に問い合わせられなかった・最終回答が空のときは失敗（`isError`）にして理由を返す（中のツールが失敗しても、回答があれば成功。「見つからなかった」も回答のため）。要約は「ツール 3 回」で、上限でまとめたら「（時間の上限でまとめた）」を足す。
- 1 回の応答で委譲できるのは 4 回まで。超えたら実行せず「この応答ではこれ以上任せられない。ここまでの結果で答える」と返す。

## 登録したドキュメントを探すツール

`search_documents`（`lib/agent/tools/knowledge/search-documents.ts`）

- 引数 `query`（500 字まで）。`lib/server/knowledge.ts` の `searchKnowledge()` で探し、見つかったチャンクを「名前 > 見出し」と本文で返す（`buildKnowledgePrompt` と同じ並べ方。しきい値・件数も同じ）。0 件なら空の結果（`isEmpty`）。
- 埋め込みの失敗（モデルが無い・Ollama に繋がらない）は `toolError` で理由を返す。
- `access: 'local'`（登録したドキュメントは手元の情報。`docs/28-rag.md`「エージェントモード」と同じ扱い）。
- **サブエージェントだけのツール**: レジストリに `subAgentOnly` の印を付けて登録し、メインの一覧（`getAllToolDefinitions`・`/api/tools`）には出さない。

## ループの共通化

今の `runAgentLoop`（`lib/agent/agent.ts`）は、ラウンドの繰り返し・ツールの実行（使えない・画像・手元を読んだ後の判定、承認、時間の上限、順番待ち）・ストリームへの中継を 1 つの関数に持つ。サブエージェントもツールの実行の規則は同じにしたいため、次の 2 つに分ける。

- **`executeToolCall`**: 1 回のツールの呼び出しを、今の判定の順（使えない → 画像 → 手元を読んだ後 → 承認 → 実行）で実行し、結果と、ループが更新する印（`unavailable`・`readLocal` 等）を返す。メインとサブエージェントの両方が使う。
- **`runSubAgent`**（`lib/agent/sub-agent-loop.ts`）: 本文をストリームへ流さずに集め（最後のラウンドの本文を回答にする）、ツールの呼び出しを記録し、最終回答の文章・記録・ラウンド数・トークン数を返す。上限のラウンド（6）に達したら、または 150 秒を過ぎたら（途中の問い合わせ・中のツールも止めて）、ツールを渡さず思考させずに（`think: false`）最終回答を作らせる。最終回答も 300 秒で止め、そのときは調べた分の記録と理由を返す（[実装で分かったこと](#実装で分かったこと)）。
- **渡していないツールは実行しない**: `executeToolCall` に「モデルへ渡していないツール」の判定を足す。設定で有効にしていない委譲のツール・サブエージェントだけの `search_documents` を、モデルが名前を覚えていて呼んでも実行しない（今までは画像のツールだけがこの形で、ほかは渡さないツールが無かった）。

サブエージェントは、メインの `ToolContext` から子の文脈を作る（後始末の登録はメインへつなぐ。「手元を読んだか」はメインの値から始め、サブエージェントの中で読んだらメインにも伝える）。

## 外部への持ち出し

今の規則（#148。`docs/14-local-file-tools.md`「外部への持ち出しを止める」）: 同じ応答の中で手元の情報を読むツールが成功した後は、外部と通信するツールを実行しない。委譲を通しても崩さない。

| 場面 | 動き |
|---|---|
| メインが手元を読んだ後（「ドキュメントを参照」の抜き出しを渡した応答を含む）に `researcher` へ委譲 | 委譲のツールの `access` が `network` のため、今の規則で**実行しない**（任せる仕事の文に手元の内容を書いて外へ出させない） |
| `reader` に委譲して成功 | 委譲のツールの `access` が `local` のため、メインも以降は手元を読んだ扱いになる（`reader` の回答には手元の内容が入る） |
| `reader` の中 | 外部と通信するツールを持たない |
| `researcher` の中 | 手元を読むツールを持たない。`researcher` は手元を読む前にしか動かないため、中で手元と外部が混ざらない |

## 記録と画面

### 記録

委譲のツールの記録（`ToolCallInfo`）に `subAgent` を足し、メッセージの `metadata.toolCalls` にそのまま保存する（JSON の中のため、DB のマイグレーションは要らない）。

```ts
type SubAgentRun = {
  agent: string; // サブエージェントの名前
  task: string; // 任せた仕事
  toolCalls: ToolCallInfo[]; // 中のツールの呼び出し（入れ子はしない）
  rounds: number; // サブエージェントの Ollama への問い合わせ回数
  metrics?: ResponseMetrics; // サブエージェントのトークン数・所要時間
};
```

- 応答のトークン数・所要時間（#31）には、サブエージェントの分も足す（応答のために使ったため）。

### 画面

- 委譲のツールの見出し: 「リサーチャーに任せる」（ツールの表示名にサブエージェントの表示名を入れる）。実行中は今のスピナーと「実行中…」。
- 結果のパネル（開いたとき）: 任せた仕事 → 中の手順（今の `ToolCallResult` を一覧で。Web の検索の結果のリンク表示もそのまま）→ 回答（Markdown）。
- 新しい部品: `features/chat/molecules/SubAgentRunDetails`（`ToolCallResult` の結果の欄から使う）。

## 設定

- 設定のモーダルのエージェントの欄に、切り替え「サブエージェントに任せる」を足す（プロンプトのプリセットの選択と同じく、エージェントモードがオンのときだけ出す）。`useAgentSettings` が `localStorage`（`agent-sub-agents-enabled`）に保存する。
- `/api/chat` のボディに `enableSubAgents`（真偽値・任意）を足す。`enableTools` が真のときだけ効く。偽・無しなら委譲のツールをモデルへ渡さない。
- `/api/tools` は、委譲のツールを一覧に含め（`subAgentOnly` のツールは含めない）、使えるサブエージェント（名前・表示名）を `subAgents` で返す。設定の画面の説明は決まった文（「Web の調べもの・手元の読みものを専用のエージェントに任せ…（応答は遅くなります）」）にした（画面は `/api/tools` を読んでいないため、説明のためだけに読みに行かない）。
- 画面（`page.tsx`）は `enableTools && enableSubAgents` を `useChat` へ渡す（エージェントモードを切っても任せる設定は残るが、送らない）。

## 上限値

| 値 | 上限 | 理由 |
|---|---|---|
| サブエージェントのラウンド | 6 | 任せる仕事は 1 つの調べもの。メイン（既定 10）より小さくし、委譲 1 回の時間を抑える |
| サブエージェントがまとめ始める時間 | 150 秒 | 過ぎたら途中の問い合わせ・中のツールも止め、ツールを渡さず思考させずに最終回答を作らせる。委譲のツールの時間で打ち切ると、調べた分も回答も失われるため（[実装で分かったこと](#実装で分かったこと)） |
| サブエージェント全体の時間 | 300 秒 | 最終回答もここで止め、調べた分の記録と理由を返す。委譲のツールの時間の上限は、止まらなかったときの保険としてこれより 30 秒長い 330 秒 |
| 委譲 1 回の時間（目安） | 300 秒 | 大きいモデルで 6 ラウンド（1 ラウンド 20〜40 秒）とページの取得が収まる。ツールの時間の上限の最大（`AGENT_TOOL_TIMEOUT_MS` の上限）と同じ |
| 1 回の応答の委譲 | 4 回 | 最悪でも 20 分で止める。[前提の調査](#前提の調査)で 1 回の応答の委譲は 2 つまでだった |
| `task` | 4,000 字 | 調査で書かれた仕事の文は 1,000 字ほど。会話の本文を丸ごと貼らせない |
| 返す回答 | 8,000 字 | プロンプトでは 2,000 字ほどを頼む。超えた分はメインの文脈を膨らませる |
| `search_documents` の `query` | 500 字 | 探す語句。埋め込みのモデルの入力を超えない |

## セキュリティ

- **サブエージェントの権限はメインを超えない**: 使うツールは、メインでも登録されている読むツールだけ（新しい `search_documents` も、メインの「ドキュメントを参照」と同じ範囲を読む）。承認が要るツール・ブラウザは持たない。
- **外部への持ち出しの規則を委譲でも当てる**: [外部への持ち出し](#外部への持ち出し)。
- **任せる仕事はモデルの書いた文**: Web の結果に仕込まれた指示でメインが委譲しても、サブエージェントができることはメインと同じ読むツールの範囲に限る。
- **停止・時間の上限で止める**: 委譲のツールの signal でサブエージェントの問い合わせと中のツールを止め、バックグラウンドに残さない。

## 実装で分かったこと

- **保存した記録を読み直すと、委譲の記録が消えていた**: メッセージの metadata を読むとき（`lib/chat/message-metadata.ts` の `parseToolCall`）は知っている項目だけを残すため、`subAgent` が捨てられ、応答の直後に見えたサブエージェントの手順が会話を開き直すと消えた（保存した記録を開く E2E で見つけた）。`parseSubAgentRun` で検証して戻すようにした（中の手順は 1 件ずつ検証し、入れ子の `subAgent` は読まない）。
- **委譲するかはモデルが使い分ける**: 実際の `/api/chat`（ツールの説明・現在の日時の節付き）で、`qwen3.8:27b` の最初のツールを 3 つの頼み方で 2 回ずつ見ると、6 回中 3 回委譲した。2 つを比べる頼み方（Next.js 16 と React 19）は 2 回とも委譲し、話題が 1 つの調べもの（Ollama の最近のリリース）は 2 回とも `web_search` を直接呼んだ。ツールの説明の「1 回の検索で済むなら自分でツールを呼ぶ」どおりで、[前提の調査](#前提の調査)（説明の短いツールだけ）より委譲は減る。
- **委譲 1 回の時間で打ち切ると、調べた分がすべて失われた**: 2 つの委譲を頼むと、1 つ目のリサーチャーは 6 ラウンド・ツール 12 回で 249 秒かかり（同じページを 2 回読んだ）、2 つ目は 300 秒の時間切れになった。時間切れでは回答も記録も残らず、メインが自分で調べ直して応答全体が 749 秒になった。まず「180 秒を過ぎたら新しいラウンドを始めない」にしたが、同じ頼み方で 2 つとも時間切れのままだった（1 ラウンドの問い合わせとページの取得に 1 分以上かかり、始めたラウンドが 300 秒をまたいだ）。そこで、180 秒で途中の問い合わせ・中のツールも止め、ツールを渡さず思考させずに（`think: false`）最終回答を作らせ、最終回答も 300 秒で止めて調べた分の記録を返すようにした（委譲のツールの時間の上限は保険の 330 秒）。リサーチャーのプロンプトに「一度読んだページは読み直さない」も足した。これで記録は残るようになったが、同じ頼み方で、1 つ目はページを 15 個読んで文脈が膨らみ、思考なしでも最終回答が残りの 120 秒に収まらず止まった（2 つ目は 275 秒で「問い合わせの上限でまとめた」）。最終回答に使える時間を広げるため、まとめ始める時間を 150 秒にした。全体では、2 つの委譲を頼むと応答に 10 分以上かかる（大きいモデルで調べものを任せる重さ。サブエージェントが読む量を減らすことは使ってから決める）。
- **ツールの名前を書き損じることがある**: メインのモデルが `delegate_to agent`（空白）と書いた呼び出しが 1 回あった。今までどおり「知らないツール」の失敗を返し、モデルは正しい名前で呼び直した。

## やらないこと

- **複数のサブエージェントを同時に動かす**: Ollama は手元の 1 つで、並べても速くならない。
- **サブエージェントごとに別のモデル**: 64GB の Mac で大きなモデルを 2 つ読み込むのは厳しい（#110・#111）。小さいモデルを読み手にする案は、精度を測ってから。
- **サブエージェントの会話を保存する**: 記録（中のツールの呼び出しと回答）だけを残す。サブエージェントの会話を開き直して続ける使い方は無い。
