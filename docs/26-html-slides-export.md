## 背景

HTML レポート・PDF・DOCX で「読んでもらう」「編集する」はできるようになった（#219・#221）。ただ、LLM に説明や提案をまとめさせて、そのまま会議で見せたいときは、1 枚ずつ大きな文字で見せるスライドの方が向いている。Markdown を区切り線や見出しで分ければ、応答の本文からそのままスライドを作れる。

## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| 応答 1 件の HTML スライド（1 ファイル。図・CSS を埋め込む） | 会話全体のスライド |
| 区切り線（`---`）・見出しでのスライドの分割 | PPTX（Phase D。後のサブ issue。分け方は共有する） |
| 矢印キー・スペースでのページ送り（スクリプトを使わない） | アプリの中のプレビュー・発表のモード |
| 応答の「保存」のダイアログにスライドを足す | スライドのテーマ・テンプレートの選択、発表者のノート |
| スライドの形で書かせるテンプレートの例（#28） | スライドの PDF の書き出し（保存したファイルを印刷すれば 1 枚 1 ページになる） |

## 決めること（レビューの論点）

| 論点 | 推奨 | 他の案 | 理由 |
|---|---|---|---|
| どこで作るか | **ブラウザの中**（HTML レポート・DOCX と同じ） | Route Handler | 図はブラウザで描く。HTML レポートの流れ（図を描く → 組み立てる → 保存）をそのまま使える |
| 変換 | **HTML レポートの変換（`renderMarkdown`。remark → rehype、図の置き換え・rehype-highlight・URL の検査）を使い、できた要素の並びをスライドに分ける** | issue の案の Marp（`@marp-team/marp-core`） | Marp は markdown-it で読むため、表・コード・生の HTML の扱いが画面・レポートとずれる。図（Mermaid・PlantUML）も描けない。ページ送りには Marp CLI のスクリプトが要る。自前なら新しい依存が要らず、安全策もレポートと同じになる |
| 対象 | **応答 1 件だけ**（応答の「保存」のダイアログ） | 会話全体も（メッセージごとに区切る） | 質問と応答が交互に並ぶ会話は発表の形にならない。スライドにしたい内容は 1 つの応答にまとめて書かせる方が自然 |
| 分け方 | **区切り線（`---`）があればそこで分ける。無ければ見出しで分ける**（最も浅い見出しの段階と、`##` までの見出しの前で切る）。どちらも無ければ 1 枚 | `---` だけで分ける / `##` だけで分ける | `---` は Marp と同じ書き方で、明示した区切りを優先する。LLM はふつう `#`・`##` の見出しで章立てするため、区切り線が無くてもスライドになる（詳しくは[スライドの分け方](#スライドの分け方)） |
| 表紙 | **足さない。1 枚目が見出しと段落だけなら、表紙の見た目（中央に大きく）にする** | 会話のタイトルと日時の表紙を必ず足す | スライドの形で書かせると、LLM は 1 枚目にタイトルを書く。必ず足すとタイトルが 2 枚続く。会話のタイトル・ページ番号は各スライドの下に小さく出す |
| ページ送り | **スクリプトを入れず、CSS の scroll-snap で 1 枚ずつ止める**（↓・↑・スペース・Page Down/Up で 1 枚ずつ進む。全画面はブラウザの全画面表示） | ←→ キー・`f` で全画面にするスクリプトを入れる | レポートと同じく、保存したファイルにスクリプトを入れない（`docs/05-security.md`。LLM の出力を含む文書でスクリプトが動く余地を作らない）。←→ キーでは進まないが、プレゼンター用のリモコンは Page Down/Up を送るため動く |
| 収まらないスライド | **縮めず、スライドの高さを伸ばす**（画面より長いスライドはそのまま下へスクロールできる。印刷では次のページへ続く） | 文字を縮める / 自動で次のスライドへ分ける | 自動で縮める・分けるには描いた大きさを測るスクリプトが要る。内容を欠けさせない |
| HTML のコメント | **スライドでは、コメントだけの生の HTML（`<!-- … -->`）を出さない**（Marp の指示・発表者のノートの書き方） | レポートと同じく文字として出す | Marp の書き方で書かせたときに、スライドに `<!-- _class: lead -->` が文字で出てしまう。消すだけで HTML として出すわけではないため、安全策は変わらない |
| front matter | **先頭の `---` で囲んだ `key: value` の行（Marp の `marp: true` 等）を取り除く** | そのまま | 残すと区切り線と見出し（`marp: true` が setext の見出しになる）に化けて、1 枚目が壊れる |
| スライドの形で書かせるテンプレート | **プロンプトテンプレートの例に 4 件目（`/slides`「スライドにまとめる」）を足す**（例は 3 件 → 4 件） | 足さない（設計書に文例だけ載せる） | issue の Phase B の項目。例は一覧が空のときに作るだけなので、今のテンプレートには影響しない |
| PDF | **スライドの PDF の形式は足さない**（保存したファイルを印刷すると、1 枚 1 ページ（横長）になる CSS を入れておく） | ダイアログに「スライド（PDF）」を足す | ダイアログの形式が 6 つになり選びにくい。要るなら後で `printHtml` を使って足せる |
| 新しい依存 | **なし** | Marp・reveal.js | 上のとおり |

## 書き出しの流れ

```
応答の「保存」のダイアログでスライドを選ぶ
  → 図を拾って描く（HTML レポートと共通。useReportExport）
  → 本文の先頭の front matter を取り除く
  → renderMarkdown（コメントだけの生の HTML を出さない指定）で要素の並びにする
  → 要素の並びをスライドに分ける（純関数。lib/chat/slides.ts）
  → スライドの HTML を組み立てる（純関数）→ `<タイトル>_<日時>.slides.html` で保存
```

- 図の描画・失敗の扱い（描けなかった図はソースのコード）は HTML レポートと同じ。
- ファイル名は HTML レポートと同じ形で、拡張子を `.slides.html` にする（同じ応答のレポートと上書きし合わないため）。

## スライドの分け方

本文の最上位のブロックの並び（HTML では `renderMarkdown` の要素の並び、PPTX では文書の中間の形の `DocBlock[]`）を、次の規則で分ける。分ける関数はブロックの種類（区切り線・見出しとその段階・段落・そのほか・空白）を返す関数を受け取る形にして、HTML と PPTX で共有する。

1. **区切り線が 1 つでもあれば、区切り線で分ける。** 区切り線そのものはスライドに入れない。見出しでは分けない。
2. **区切り線が無ければ、見出しで分ける。** 本文の中で最も浅い見出しの段階を `d` として、段階が `max(d, 2)` 以下の見出しの前で切る。
   - `#`・`##`・`###` がある → `#` と `##` の前で切る（`###` はスライドの中の小見出し）
   - `##`・`###` だけ → `##` の前で切る
   - `###` だけ → `###` の前で切る
   - 最初の見出しより前の本文は、それだけで 1 枚にする
3. どちらも無ければ、本文全体を 1 枚にする。
4. 空のスライド（区切り線が続く・末尾の区切り線）は捨てる。本文が空なら、会話のタイトルだけの表紙を 1 枚にする。
5. **表紙**: 1 枚目が「見出しを含み、見出しと段落だけ」のとき、表紙の見た目にする。

## スライドの見た目と操作

- 1 つの HTML ファイル（`<!doctype html>`・`<title>` に会話のタイトル・`<style>`。スクリプトは入れない）。
- スライドは 16:9 を目安に、画面いっぱい（幅 100vw・高さ 100vh 以上）。中身は幅 1100px 程度までの中央。文字は画面の幅に合わせて大きさを変える（`clamp()`）。
- 明るい背景・Nord の青のアクセント（HTML レポートと同じ色）。コードの色付け・表・引用・図はレポートの CSS に合わせる。図・画像は画面の高さの 70% までに縮める。
- 各スライドの下に、左に会話のタイトル、右に `3 / 12` のページ番号（組み立てるときに書き込む）。中断した応答は、最後のスライドに「（生成を中断した応答）」の注記。
- ページ送り: `html` に `scroll-snap-type: y mandatory`、スライドに `scroll-snap-align: start`。↓・↑・スペース・Page Down/Up で 1 枚ずつ止まる。全画面はブラウザの全画面表示（F11・⌃⌘F）。
- 印刷: `@page { size: 16:9 の横長; margin: 0 }`、スライドごとに改ページ（PDF にすれば 1 枚 1 ページ）。

## スライドの形で書かせるテンプレート

プロンプトテンプレートの例（`app/api/prompt-templates/examples/route.ts` の `EXAMPLE_TEMPLATES`）に足す。

| ショートカット | 名前 | 本文 |
|---|---|---|
| `slides` | スライドにまとめる | 以下の内容を発表用のスライドにまとめてください。1 枚目はタイトルのスライドにし、スライドの間は `---` だけの行で区切り、各スライドは `## 見出し` で始めて箇条書きを 3〜5 個にしてください。 |

- 例は「一覧が空のときに作る」ため、今のテンプレートには入らない。今テンプレートがある人は、この文例を自分で登録する（設計書の文例を参照）。

## 画面

- 応答の「保存」のダイアログ: Markdown・HTML・PDF・DOCX・**スライド**の順。会話の書き出しのダイアログには出さない。
- 説明は「ブラウザで開いて発表できるスライドで保存する（`---` か見出しで 1 枚ずつ分ける）」。アイコンは lucide の `Presentation`。


## やらないこと

- 会話全体のスライド
- PPTX（Phase D。後のサブ issue。`lib/chat/slides.ts` の分け方を使い回す）
- アプリの中のプレビュー・発表のモード、←→ キー・全画面のキー（スクリプトが要る）
- スライドのテーマ・テンプレートの選択、発表者のノート、スライドの切り替えの動き
- 収まらないスライドの自動の縮小・分割
- スライドの PDF の形式（保存したファイルを印刷すれば 1 枚 1 ページになる）
