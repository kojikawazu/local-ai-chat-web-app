## 背景

HTML レポート・PDF で「読んでもらう」ことはできるようになった（#219）。ただ、受け取った人が手を入れて社内の資料にしたり、Word の書式に合わせて提出したりするには、編集できる DOCX の方が都合がよい。

## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| 応答・会話の DOCX（見出し・段落・強調・リスト・表・コード・引用・区切り線・リンク） | コードの色付け |
| 図（Mermaid・PlantUML を PNG にして埋め込む）・添付画像 | Word のテンプレート（スタイル）の選択 |
| 書き出しのダイアログに DOCX を足す | HTML スライド・PPTX（後のサブ issue） |

## 決めること（レビューの論点）

| 論点 | 推奨 | 他の案 | 理由 |
|---|---|---|---|
| どこで作るか | **ブラウザの中**（HTML レポートと同じ） | issue の案の Route Handler（`GET /api/export/docx`） | 図はブラウザで描く。画像もブラウザで読める。HTML と同じ流れ（図を描く・画像を読む）を使い回せる |
| ライブラリ | **npm の `docx`**（9.12.0。公開から 2 週間以上の版） | pandoc（外部のコマンド） | 純粋な JavaScript でブラウザでも動く（issue の案どおり）。pandoc はサーバーに入れる手間がかかる |
| 読み込み方 | **DOCX を選んだときだけ読み込む**（`import('docx')`） | 画面を開いたときに読み込む | 大きいライブラリ（展開して約 20MB。実際に読み込む量はその一部）を、使わない人に読み込ませない。Mermaid と同じ扱い |
| 変換の作り | **Markdown → 文書の中間の形（純関数）→ DOCX の 2 段** | Markdown の構文木から直接 DOCX の部品を作る | 中間の形なら、`docx` を使わずに UT で中身を確かめられる。後の PPTX（スライド）も同じ中間の形から作れる |
| Markdown の解釈 | **HTML レポートと同じ remark-parse・remark-gfm**（構文木は mdast。生の HTML は文字、リンクは `defaultUrlTransform` で検査、本文の画像はリンク） | — | HTML レポート・画面と解釈を揃え、安全策も同じにする |
| コード | **等幅のフォント（Consolas）・薄い背景の段落。色付けはしない** | rehype-highlight のクラスを文字の色に移す | Word のコードは色が無くても読める。色付けは手間に対して効果が小さい。要るなら後で足せる |
| 図 | **HTML と同じく描いた SVG を、PNG にして埋め込む**（白い背景・2 倍の解像度。`svgToPngBlob` を使い回す）。描けなければソースのコード | SVG のまま入れる | Word の SVG は、古い Word で見えないため PNG の代わりの画像が要る。PNG だけなら どの Word でも見える |
| 画像の大きさ | **本文の幅（A4 の余白を除いた約 16cm）に収まるように縮める**（小さい画像は元の大きさ） | 元の大きさ | 大きな図・画面のキャプチャがページからはみ出さないようにする |
| 中身 | **HTML レポートと同じ**（会話全体: タイトル・書き出した日時・役割・メッセージ。応答 1 件: その応答の本文。思考過程・ツールの結果は入れない） | — | 形式で中身が変わらないようにする |
| 見出しの段階 | **メッセージの見出し（ユーザー / アシスタント・日時）を見出し 1、本文の `#`〜`###` を見出し 2〜4 にする**（`####` 以降は見出し 4） | 本文の `#` を見出し 1 にする | Word のナビゲーションで、メッセージごとにまとまって見える。本文の見出しがメッセージの見出しと同じ段に並ばない |
| 見た目 | **Word の組み込みのスタイル（表題・見出し 1〜4・表）と游ゴシック。A4・余白 20mm** | 独自のスタイル | 受け取った人が Word で見出しの書式を変えやすい。目次も作れる |
| 新しい依存 | **`docx`（本体）と、テストで中身を読むための `jszip`（dev。`docx` が使っているのと同じ 3.10.1）** | テストで中身を読まない | 保存した DOCX の中（`word/document.xml`）を E2E で確かめるため |

## 書き出しの流れ

```
書き出しのダイアログで DOCX を選ぶ
  → 図を拾って描く・添付画像を読む（HTML レポートと共通）
  → 図の SVG を PNG にする（DOCX だけ）
  → Markdown を文書の中間の形にする（純関数）
  → import('docx') → 中間の形を DOCX の部品にする → Packer.toBlob → 保存
```

- 図を描く・画像を読む処理は、HTML レポートのフック（`useReportExport`）から関数に切り出して共有する。
- 失敗の扱いは HTML と同じ（描けなかった図はソースのコード、読めなかった画像は注記。DOCX の組み立てそのものの失敗だけダイアログにエラー）。

## 文書の中間の形

Markdown（mdast）を、Word・スライドに移しやすいブロックの並びにする。`docx` に依存しない純粋なデータ。

| ブロック | 中身 |
|---|---|
| `heading` | Markdown の段階（1〜6。Word の見出しの段階は書き出す側で決める）・文字の並び |
| `paragraph` | 文字の並び（`text`・強調・斜体・取り消し線・インラインのコード・リンク・改行） |
| `list` | 番号付きか・項目（項目ごとにブロックの並び。入れ子あり）・タスクのチェック |
| `table` | 列の揃え・行（見出しの行と本文の行）・セル（文字の並び） |
| `code` | 言語・本文 |
| `quote` | ブロックの並び |
| `image` | 図・添付画像（PNG / JPEG のバイト列・幅・高さ・代わりの文字） |
| `rule` | 区切り線 |
| `note` | 注記（読めなかった画像・中断した応答） |

- 図のコードブロックは、描けた図（PNG）があれば `image`、無ければ `code` にする。
- リンクは `defaultUrlTransform` を通り、危ない URL は文字だけにする。本文の画像はリンク（安全な URL のとき）か文字にする。
- 生の HTML（`html` のノード）は文字にする。

## Word の書式への対応

| 中間の形 | Word |
|---|---|
| 文書のタイトル | 組み込みの「表題」 |
| メッセージの見出し（ユーザー / アシスタント・日時） | 見出し 1 |
| 本文の見出し `#`・`##`・`###` | 見出し 2・3・4（`####` 以降は見出し 4） |
| 強調・斜体・取り消し線 | 太字・斜体・取り消し線 |
| インラインのコード・コードブロック | Consolas・薄い灰色の網掛け |
| リンク | 外部へのハイパーリンク（青・下線） |
| リスト | 箇条書き・番号付き（入れ子は字下げ）。タスクは `☐` / `☑` |
| 表 | 罫線付きの表。見出しの行は網掛け・太字 |
| 引用 | 左の罫線と字下げ |
| 区切り線 | 下の罫線の段落 |
| 画像 | 本文の幅に収めた画像（中央揃え） |

## 画面

- 会話の書き出しのダイアログ: Markdown・HTML・PDF・**DOCX**・JSON の順。
- 応答の「保存」のダイアログ: Markdown・HTML・PDF・**DOCX** の順。
- 説明は「Word で編集できるファイルで保存する（図・画像も入る）」。

## ファイル構成

```
front/src/
├── lib/chat/document-model.ts           # Markdown（mdast）→ 文書の中間の形（純関数。HTML と同じ安全策）
├── lib/chat/report-docx.ts              # 中間の形 → docx の部品（docx を引数で受ける。読み込みは呼び出し側）
├── lib/chat/report-assets.ts            # 図を描く・添付画像を読む（HTML・DOCX で共有。useReportExport から切り出す）
├── hooks/chat/useReportExport.ts        # 形式に docx を足す（図の PNG・import('docx')・Packer・保存）
└── components/features/chat/organisms/ExportDialog.tsx  # DOCX の形式を足す
```

- `lib/chat/report-docx.ts` は `docx` の型だけを import し、本体は呼び出し側が `import('docx')` で読み込んで渡す（静的に import すると画面の最初の読み込みに入るため）。

## テスト

| 層 | 対象 |
|---|---|
| UT（`document-model.test.ts`） | 見出し（Markdown の段階のまま）・段落の強調 / 斜体 / 取り消し線 / コード / 改行・リスト（番号・入れ子・タスク）・表（揃え・見出しの行）・コード・引用・区切り線・図（描けた図は画像・描けなかった図はコード）・安全策（生の HTML は文字・`javascript:` のリンクは文字・本文の画像はリンクか文字）・空の本文 |
| UT（`report-docx.test.ts`） | 中間の形から DOCX を作り（node の `docx`）、`jszip` で `word/document.xml` を読んで、見出しのスタイル（メッセージは見出し 1・本文の `#` は見出し 2・`####` 以降は見出し 4）・表・ハイパーリンク・画像・注記が入ることを確かめる |
| IT | 対象なし（API・DB を変えない） |
| E2E（`report-export.spec.ts` に足す） | 会話・応答を DOCX で保存し、ファイル名（`.docx`）と、`word/document.xml` にタイトル・見出し・表の文字・画像（`word/media/`）が入ること。描けなかった図はソースの文字が入ること |

## やらないこと

- コードの色付け
- Word のテンプレート（スタイル）の選択・カスタマイズ
- 目次・ページ番号・ヘッダー / フッター
- HTML スライド・PPTX（後のサブ issue。中間の形を使い回す）
- 思考過程・ツールの結果を入れること（HTML レポートと同じ）
