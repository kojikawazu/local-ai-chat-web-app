## 範囲

| 含める | 含めない（[やらないこと](#やらないこと)） |
|---|---|
| コマンドを 1 つ実行して、終わるまで待ち、出力と終了コードを返す（`run_command`） | パイプ・リダイレクト・`&&` などのシェルの機能 |
| 実行してよいプログラムの許可リスト・作業フォルダの制限 | 終わらないコマンド（開発サーバー・監視モード）を裏で動かし続けること |
| 毎回の承認（コマンド・作業フォルダを見せる） | 標準入力への入力（対話的なコマンド） |
| タイムアウト・出力の上限・停止での中断（子のプロセスまで止める） | 実行中の出力を逐次画面に流すこと |

## 決めること（レビューの論点）

| 論点 | 推奨 | 他の案 | 理由 |
|---|---|---|---|
| 引数の形 | **1 つの文字列**（`"pnpm test:unit tests/unit/calculate.test.ts"`）を受け、アプリが引数の配列に分ける | 引数の配列（`["pnpm", "test:unit", ...]`）を受ける | 小さいモデルは配列の引数を組み立て損ねやすい。分けた結果（配列）は承認カードに見せ、シェルは介さずに実行するので、安全性は配列で受けるのと変わらない |
| 実行してよいもの | 環境変数 **`LOCAL_COMMANDS`**（プログラム名のカンマ区切り）。未設定ならツールを登録しない | コードに固定の許可リスト | 書き込み（`LOCAL_FILE_WRITE_ROOTS`）と同じく、利用者が自分で範囲を決めて初めて使えるようにする。使うプログラムは人によって違う |
| 作業フォルダ | **`LOCAL_FILE_WRITE_ROOTS` の中**に限る | `LOCAL_FILE_ROOTS`（読み取り）の中 | コマンドはファイルを書き換えうる（`pnpm format`・`git checkout`）。書いてよい範囲より広くしない |
| 承認 | **毎回**（読み取りだけのコマンドも） | 読み取りだけのコマンド（`git status` 等）は承認なし | 読み取りだけかどうかの判定は引数しだいで崩れる（`git log --output=<file>` は書く・`git diff` は外部のプログラムを呼べる）。まずは毎回で使ってみる |
| ファイルを読んだ後の実行 | **止めない**（承認が守り）。実行が成功したら、その応答では `web_search`・`url_fetch` を止める | ファイルを読んだ後は止める（`network` と同じ扱い） | 「コードを読む → テストを回す」が目的の使い方。止めると目的を果たせない |
| タイムアウト | 環境変数 **`LOCAL_COMMAND_TIMEOUT_MS`**（既定 120 秒・上限 10 分）。ツール全般の `AGENT_TOOL_TIMEOUT_MS`（30 秒）とは別 | `AGENT_TOOL_TIMEOUT_MS` をそのまま使う | テスト・ビルドは 30 秒で終わらない。ツール全般の上限を上げると、Web の取得が止まったときの待ちまで長くなる |

## ツール

### `run_command`

| 引数 | 必須 | 説明 |
|---|---|---|
| `command` | ○ | 実行するコマンド（例: `git status`・`pnpm test:unit`）。パイプ・リダイレクト・`&&` は使えない |
| `cwd` | ○ | 作業フォルダの絶対パス（書き込んでよいフォルダの中） |

- モデルへの説明には、許可しているプログラムの一覧と作業フォルダの一覧を入れる（`list_directory` が読んでよいフォルダを説明に入れるのと同じ）。
- 準備（`prepare`）で「解釈 → 許可リスト → 実行ファイルの場所 → 作業フォルダ」を確かめ、どれかで失敗したら理由を返して承認を求めない。

## コマンドの解釈

文字列を、シェルを使わずに引数の配列に分ける（`lib/agent/tools/local-commands/parse.ts`。自前の小さな解釈で、外部のライブラリは足さない）。

| 書き方 | 扱い |
|---|---|
| 空白 | 引数の区切り |
| `'...'` | 中身をそのまま 1 つの引数の一部にする |
| `"..."` | 中身を 1 つの引数の一部にする。`\"` と `\\` だけ解釈する |
| `\`（クォートの外） | 次の 1 文字をそのまま使う |
| クォートの外の `\|` `&` `;` `<` `>` `` ` `` `$(` `(` `)` | **断る**（「パイプ・リダイレクト・つなげての実行はできません。コマンドを 1 つずつ実行してください」） |
| クォートの外の `*` `?` `~` `$VAR` | 展開しない（そのままの文字として渡す）。モデルへの説明に「ワイルドカード・変数は展開されない」と書く |
| 閉じていないクォート・空の文字列 | 断る |

- シェルの記号を「断る」のは、モデルが `pnpm test | tail -20` のようにシェルのつもりで書いたとき、`|` がただの引数として渡って意図しない動きになるのを防ぐため（シェルを介さないので、通しても注入にはならない）。
- 引数の数は 100 個・全体の長さは 4,000 文字まで。

## 実行してよいコマンド（LOCAL_COMMANDS）

| 環境変数 | 説明 | 既定 |
|---|---|---|
| `LOCAL_COMMANDS` | 実行してよいプログラムの名前（カンマ区切り。例: `git,pnpm,gh,ls`） | 未設定（ツールを使わない） |

- 照合するのは**最初の引数（プログラム名）だけ**。名前は `/` を含まないこと（`./script.sh`・`/usr/bin/git` のようなパスは断る）。サブコマンド（`git push` 等）までは見ない（[承認](#承認)が守り）。
- プログラムは、サーバーの `PATH` から探して実体のパスにする（準備のとき）。承認カードにはその実体のパスを見せ、許可されたらそのパスを実行する。見つからなければ、承認を求めずに「見つかりません」と返す。
- **許可リストに書いても使わないもの**（`console.warn` で知らせて外す）: シェル（`sh`・`bash`・`zsh`・`fish`・`dash`・`ksh`・`csh`・`tcsh`）と、別のプログラムを起動するためのもの（`sudo`・`su`・`doas`・`env`・`xargs`・`nohup`・`nice`・`time`・`timeout`）。これらを通すと、許可リストとシェルを介さない方針の両方を素通りできるため。
- `node`・`python`・`pnpm`（`pnpm exec`・スクリプト）などは任意のコードを実行できる。書くかどうかは利用者に任せ、マニュアル・`.env.example` に「書いたプログラムは何でも実行できる前提で選ぶ（承認が最後の守り）」と注意を書く。`curl`・`wget` など外へ送るためのものは書かないよう勧める。

## 作業フォルダ

- `cwd` は `realpath` で実体にしてから、`LOCAL_FILE_WRITE_ROOTS` のどれかの中にあることを確かめる（書き込みのツールの判定 `isWithinRoot` を使う）。
- `.git` の中・秘匿フォルダ（`.ssh` 等。Phase A と同じ範囲）は断る。
- `LOCAL_FILE_WRITE_ROOTS` が空なら、`LOCAL_COMMANDS` があってもツールを登録しない（`console.warn` で知らせる）。

## 実行のしかた

- `child_process.spawn(実体のパス, 引数, { cwd, shell: false, detached: true, stdio: ['ignore', 'pipe', 'pipe'], env })`。
  - `shell: false`: シェルを介さない。
  - `detached: true`: 新しいプロセスグループを作る。止めるときに `process.kill(-pid, 'SIGTERM')` で**子・孫のプロセスまで**止めるため（`pnpm test` は vitest のワーカーを起動し、親だけ止めると残る）。3 秒で終わらなければ `SIGKILL`。
  - 標準入力は閉じる（`ignore`）。入力を待つコマンドが止まらないようにする。
- **環境変数は絞って渡す**: サーバーの環境変数のうち `PATH`・`HOME`・`USER`・`LOGNAME`・`LANG`・`LC_ALL`・`LC_CTYPE`・`TMPDIR` だけを引き継ぎ、次を足す。`DATABASE_URL`・`OLLAMA_*` などアプリの設定はコマンドに渡さない。

  | 足す変数 | 理由 |
  |---|---|
  | `NO_COLOR=1`・`FORCE_COLOR=0`・`TERM=dumb` | 色の制御文字を減らす（残ったものは出力から取り除く） |
  | `GIT_TERMINAL_PROMPT=0`・`GIT_PAGER=cat`・`PAGER=cat` | 認証の入力・ページャーで止まらないようにする |
  | `GH_PROMPT_DISABLED=1` | `gh` の対話を止める |

- 止まる条件: 終了・タイムアウト（`LOCAL_COMMAND_TIMEOUT_MS`）・停止ボタン／切断（ループの `signal`）。どれでもプロセスグループごと止める。
- ツールの実行時間の上限（ループの `withToolTimeout`）は、ツールが持つ上限を使えるようにする（`Tool` に任意の `runTimeoutMs` を足す）。`run_command` は `LOCAL_COMMAND_TIMEOUT_MS` + 10 秒にする。ツールの中で先に止めて、途中までの出力を返せるようにするため（ループの上限は、ツールが止まらなかったときの保険）。

## 出力と結果

- 標準出力と標準エラー出力を、届いた順に 1 つにまとめる。色などの制御文字（ANSI のエスケープ）は取り除く。
- モデルへ返す出力は **30,000 文字まで**。超えたら**先頭 5,000 文字と末尾 25,000 文字**を残し、間に「…（N 文字を省略）…」と書く（テストの失敗・エラーは末尾に出ることが多いため、末尾を多く残す）。読みながら先頭と末尾だけを持ち、メモリに全体を溜めない。

| 結果 | `isError` | 画面の要約（`summary`） | モデルへ返す文章 |
|---|---|---|---|
| 終了コード 0 | false | `終了コード 0` | コマンド・作業フォルダ・終了コード・出力 |
| 終了コード 0 以外 | true | `終了コード 1` | 同上（失敗の出力をモデルが読んで直せるように） |
| タイムアウト | true | `120 秒で止めました` | 「タイムアウトで止めました」と途中までの出力 |
| シグナルで終了 | true | `SIGKILL で終了` | 同上 |
| 起動できない | true | 理由 | 理由（実行ファイルが消えた等） |
| 出力なし・終了コード 0 | false | `終了コード 0・出力なし` | 出力の欄に「（出力なし）」 |

- 出力の無い成功（`git add` 等）はコマンドでは普通のため、検索の 0 件のような空振り（`isEmpty`。⚠️）にはしない。
- 所要時間は画面がツールの結果の欄に別に出すため、要約には入れない。

- 拒否・時間切れの扱いは Phase A2 と同じ（[15-tool-approval.md「承認の結果」](./15-tool-approval.md#承認の結果)。文章の「書き込み」を「実行」にする）。

## 承認

承認の流れ・承認の API・承認待ちの持ち方は Phase A2 のものをそのまま使う。変えるのは見せる内容だけ。

- `ApprovalPreview` を、何をするか（`action`）で分ける union にする。

  ```ts
  type FileApprovalPreview = {
    action: 'create' | 'overwrite' | 'edit';
    path: string; diff: string; added: number; removed: number;
  };
  type CommandApprovalPreview = {
    action: 'run';
    command: string;     // 引数の配列を、区切りが分かるようにクォートし直した 1 行
    executable: string;  // 実行ファイルの実体のパス（/opt/homebrew/bin/pnpm 等）
    cwd: string;         // 作業フォルダの実体のパス
    timeoutMs: number;   // タイムアウト
  };
  type ApprovalPreview = FileApprovalPreview | CommandApprovalPreview;
  ```

- **承認カード**（`ApprovalCard`）は `action` で出し分ける。コマンドのときは、見出し「コマンドを実行します」・コマンド（等幅）・実行ファイルの実体のパス・作業フォルダ・タイムアウトを出す。ボタンは同じ（許可・拒否）。
- 見せるコマンドは、モデルが書いた文字列ではなく**分けた結果をクォートし直したもの**にする（`'a b'` と `a b` の違い＝引数の区切りが分かるように）。

## 外部への持ち出しとの関係

Phase A の「ローカルのファイルを読んだ後は、外部への通信のツールを止める」（[14-local-file-tools.md](./14-local-file-tools.md#外部への持ち出しを止める)）との関係。

- `run_command` は `access: 'local'` とする。ファイルを読んだ後でも止めない（承認が守り）。
- `run_command` が成功したら、その応答の中では `web_search`・`url_fetch` を止める（コマンドの出力にローカルの中身が含まれるため。ファイルを読んだときと同じ）。
- コマンド自体が外へ送れる（`gh`・`git push`・`curl`）ことは、この仕組みでは止められない。**毎回の承認でコマンドの全体を見せること**と、許可リストに外へ送るためのプログラムを書かないことで守る。

## 上限値

| 対象 | 上限 | 根拠 |
|---|---|---|
| コマンドの文字列 | 4,000 文字・引数 100 個 | 普通のコマンドで足りる。長いものは承認カードで読めない |
| 実行時間（`LOCAL_COMMAND_TIMEOUT_MS`） | 既定 120 秒・上限 600 秒 | ユニットテスト・型チェックが収まる長さ。ストリームを開いたまま待つため、際限なくは待たない |
| モデルへ返す出力 | 30,000 文字（先頭 5,000・末尾 25,000） | `read_file` の上限（2,000 行）と同じくらいの量。モデルの文脈を出力で埋めない |
| 止めるときの猶予 | `SIGTERM` から 3 秒で `SIGKILL` | 後片付けの時間を与えつつ、止まらないプロセスを残さない |

## 脅威と対策

| 脅威 | 例 | 対策 |
|---|---|---|
| 指示を仕込まれて実行する | Web の結果に「`rm -rf` を実行して」 | **毎回の承認**（コマンドの全体・実行ファイル・作業フォルダを見せる）。許可リストに無いプログラムは準備で断る |
| 許可リストを素通りする | `bash -c "..."`・`env rm ...`・`sudo ...`・`./evil.sh` | シェルを介さない。シェルと、別のプログラムを起動するもの（`env`・`sudo`・`xargs` 等）は許可リストに書いても外す。パスでの指定は断る |
| シェルの記号で別のコマンドをつなぐ | `git status; curl ...` | シェルを介さないので効かない。加えて、クォートの外のシェルの記号は断る |
| アプリの秘密を読ませる | `printenv`・`node -e "console.log(process.env)"` | コマンドに渡す環境変数を絞る（アプリの設定を渡さない） |
| 外へ送る | `gh gist create .env`・`curl -d @file ...` | 承認。外へ送るためのプログラムを許可リストに書かないよう勧める。秘匿ファイルを引数に取る形は完全には止められない（承認で見る） |
| 許可していない場所で実行する | `cwd` に `/`・`~` | 作業フォルダは書き込んでよいフォルダの中だけ（実体のパスで判定） |
| 止まらない・残る | 監視モード・入力待ち・孫のプロセス | 標準入力を閉じる・対話を止める環境変数・タイムアウト・プロセスグループごと止める |
| 出力で埋まる | 巨大なログ | 先頭と末尾だけを持つ（メモリも上限まで） |

## やらないこと

- **シェルの機能**（パイプ・リダイレクト・`&&`・ワイルドカード）: 1 つずつ実行させる。要るとなれば、シェルを介さずに組み合わせる形で検討する。
- **終わらないコマンドを裏で動かす**（`pnpm dev` 等）: タイムアウトで止まる。動かし続ける・後から出力を見る仕組みは別に考える。
- **一括の承認・読み取りだけのコマンドの承認の省略**: 使ってみて、`git status` などの承認が煩わしければ、範囲を絞って検討する。
- **実行中の出力を逐次画面に流す**: 終わってから結果を出す。長いテストで要るとなれば、イベントを足して検討する。
- **GitHub の PR の操作（Phase C）**: `gh` を許可リストに書けば `run_command` でできるが、試した結果、読むだけでも毎回の承認が要ることと `gh api` 等まで通ることから、専用のツールにした（[17-github-tools.md](./17-github-tools.md)）。
