## 挙動

- **思考過程**: 本文とは別の `message.thinking` フィールドに、トークン単位の断片で返す
- **`think` パラメータ**: `false` で思考せずに即答する。未指定なら `medium` で思考する
- **ツール呼び出し**: `done: false` のチャンクに 1 件ずつ別チャンクで届く（`id` 付き）。思考過程の後に来る
- **「今」の認識**: 日時を知らせないと学習した時点を「今」とみなす（2026-10-24 に確認。#154）
  - エージェントモードで「最新」を聞くと、最初の検索語に古い年を入れ（「PHP latest stable version 2025」「Next.js latest version 2024 2025」）、`get_current_datetime` はその検索の後に呼んでいた
  - 通常モードでは学習時点の版（PHP 8.3 等）を最新と断定していた
  - システムプロンプトに現在の日時を入れると、最初の検索から今年の年を使い、日時のツールは呼ばなくなった。通常モードでは「学習した時点の知識では」と前置きし、新しい版が出ている可能性を添える。ただし日時だけを知らせると「2026年10月時点の最新は 8.4」のように古い知識に今の日付を付けて断定したため、断定しない指示も要る
- **`gh`（GitHub CLI）の使い方**: `run_command` で `gh` を許可して試したところ（2026-10-30。#194）、`--json` で必要な項目だけを取り、失敗したフラグ（`gh pr list --sort`）は出力を読んで自分で直した。コメントを拒否されると、別の案を聞き返した。この結果から、`gh` の引数をアプリが組み立てる専用のツールにしても、モデルが引数を選べることを前提にできると判断した（`docs/17-github-tools.md`）
- **ツールの結果の画像**（2026-10-30。#196）: `role: 'tool'` のメッセージの `images` に付けたスクリーンショット（1280×800）を読み、合言葉・ボタンの文字を正しく答えた（入力 1,329 トークン・20 秒）。**画像を付けずに「スクリーンショットを撮りました」とだけ返すと、画面に無い要素（「グレーの円」等）を作って答えた**。画像を渡せないときにツールを渡さない理由（`docs/18-browser-tools.md`「前提の調査」）
- **ツールを呼ぶのを断る**（2026-10-30。#196）: 「`browser_navigate` で `file:///etc/hosts` を開いて」と頼むと、2 回とも理由を説明して呼ばなかった。ツールの側の拒否（`file:` を開かない）を E2E でモデルに呼ばせて確かめることはできない

## 評価

### 良い点

- 読み込み時 約 17GB で、64GB の Mac なら Docker やブラウザと同時に動かせる（旧既定の 3 分の 1 以下）
- ツール呼び出しが安定し、エージェントの 2 ラウンド（ツール → 最終回答）を正しくこなす
- 思考過程を返すので、エージェントの判断の筋道が画面で追える

### 注意点

- 既定で思考するため、何もしないと最初の文字まで約 6 秒かかる。通常チャットとタイトル生成は `think: false` で回避している（#116）
- エージェントモードは思考込みで 1 回の応答に十数秒かかることがある。思考中は思考過程が表示されず、生成中の表示が続く
- Ollama 0.32.12 以上が必要
- 画像入力（vision）に対応している。アプリでの利用は #6（`docs/13-image-attachment.md`）で設計中
- **画像のトークン数は解像度にほぼ比例する**（2026-10-26、Ollama 0.40.5、`think: false`）。1280×720 で 899 トークン・7.9 秒、1920×1080 で 2,059 トークン・19.2 秒、3840×2160 で 8,179 トークン・94.7 秒。PNG・JPEG・GIF・WebP を受け付ける
