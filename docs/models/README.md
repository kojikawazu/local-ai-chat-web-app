# LLM モデル評価

> 最終更新: 2026-10-17

本プロジェクトで使っている Ollama モデルの仕様・実測値・挙動の違いをまとめる。モデルを選び直すとき、またはモデルの違いでアプリの挙動が変わったときに参照する。

| モデル | 本プロジェクトでの役割 | ひとことで |
|---|---|---|
| [`qwen3.8:27b`](./qwen3.8-27b.md) | **アプリの既定**（#111 以降） | 思考・ツール・画像に対応。旧既定の 3 分の 1 以下のメモリで動く |

## 比較

仕様は `ollama show <モデル>`・`ollama list`、メモリは `ollama ps` の値。

| 項目 | `qwen3.8:27b` | `qwen3-coder-next:latest` | `qwen2.5:0.5b` |
|---|---|---|---|
| パラメータ数 | 27.8B | 79.7B | 494M |
| 文脈長 | 262,144 | 262,144 | 32,768 |
| 必要な Ollama | **0.32.12 以上** | 0.15.5 以上 | 指定なし |
| 対応機能 | completion / tools / **thinking** / vision | completion / tools | completion / tools |
| ファイルサイズ | 18GB | 51GB | 397MB |
| 読み込み時のメモリ | 約 17GB | 約 58GB | 約 750MB |
| ツール呼び出し | 安定 | 安定 | 不安定 |
| 思考過程 | `message.thinking` で返す | なし | なし |

## 挙動の違い（実装への影響）

モデルによって Ollama の応答の形が変わる。アプリはどの形でも動くように実装している（`front/src/lib/agent.ts` の `readOllamaResponse`）。

### 思考過程の返し方

| モデル | 返し方 | アプリでの扱い |
|---|---|---|
| `qwen3.8:27b` | 本文とは別の `message.thinking` フィールドに、トークン単位の断片で返す | 1 回の応答の間ためておき、本文かツール呼び出しが届いた時点で 1 つの `thinking` イベントにする（#116） |
| `<think>` タグを書くモデル（qwen3 系の一部） | 本文（`message.content`）の中に `<think>...</think>` で書く | 状態マシンでタグを検出し、`thinking` イベントに分ける |
| `qwen3-coder-next` / `qwen2.5:0.5b` | 思考しない | — |

`message.thinking` の断片を個別に送らないのは、`thinking` イベントが送信前に `trim()` されるため。断片（`' user'` のように先頭に空白を持つ）ごとに送ると単語間の空白が消える。

### think パラメータへの反応

Ollama の `/api/chat` に `think` を付けたときの反応。

| モデル | `think: false` | `think: true` | 未指定 |
|---|---|---|---|
| `qwen3.8:27b` | 思考せずに即答する | 思考する | 思考する（`medium`） |
| `qwen2.5:0.5b`（思考非対応） | **エラーにならず普通に答える** | **エラー**（`does not support thinking`） | 普通に答える |

このため、アプリはモデルを確かめずに `think: false` だけを送る（通常チャット・タイトル生成）。エージェントモードは `think` を送らず、モデルの既定に任せる（#116）。

### ツール呼び出しの返し方

| モデル | `tool_calls` の出方 |
|---|---|
| `qwen3.8:27b` | `done: false` のチャンクに **1 件ずつ別チャンク**で届く（`id` 付き）。思考過程の後に来る |
| `qwen3-coder-next` | `done: false` のチャンクに**まとめて**届く。並列呼び出しは `index` で区別 |
| `qwen2.5:0.5b` | 呼び出すかどうか・引数が安定しない |

アプリはチャンクごとに `tool_calls` を集めるため、どちらの出方でも動く。

## 運用上の注意

- **`.env.local` の `OLLAMA_MODEL` が既定値より優先される。** 既定モデルを変えても、`front/.env.local` に古いモデル名が書いてあればそちらが使われる
- **E2E は `E2E_OLLAMA_MODEL`（既定 `qwen2.5:0.5b`）で決まる。** アプリの既定モデルとは独立している。大きいモデルで回すときは `E2E_OLLAMA_MODEL=qwen3.8:27b pnpm test:e2e`
- **大きいモデルは使い終わったら解放する。** `ollama ps` で読み込み中のモデルを確認し、`ollama stop <モデル>` で解放する。GPU に載ったモデルはスワップできない

## モデルを追加・変更するとき

### 確認項目

1. `ollama show <モデル>` で必要な Ollama のバージョン・対応機能（tools / thinking）・文脈長を確認する
2. `ollama ps` で読み込み時のメモリを測る（文脈長が長いとファイルサイズより大きくなる）
3. 思考過程の返し方（`message.thinking` / `<think>` タグ / なし）と、`think: false` への反応を確認する
4. `E2E_OLLAMA_MODEL=<モデル> pnpm test:e2e` でエージェント系の E2E を回す
5. 既定にする場合は、`.claude/rules/documentation.md` の「重複している事実」に従って転記箇所を同期する

### このディレクトリの更新

- モデルごとに `<モデル名>.md` を追加する（タグの `:` は `-` に置き換える。例: `qwen3.8:27b` → `qwen3.8-27b.md`）
- 本ファイルの「モデル一覧」「比較」と、挙動に違いがあれば「挙動の違い」に追記する
- 各ファイル冒頭の「最終更新」と、数値を測った日付・Ollama のバージョンを書く
