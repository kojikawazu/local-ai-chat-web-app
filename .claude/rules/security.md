# セキュリティ

## 認証・認可

- **認証不要**（localhost 個人利用のため）。

## インジェクション対策

- **SQL インジェクション**: Prisma Client のパラメータバインディングを必須とする。`$queryRaw` での文字列結合は禁止。
- **XSS**: 生の HTML 埋め込みは禁止。Reactの標準エスケープを活用。Markdown表示は `react-markdown` を使用（HTML パースなし）。シンタックスハイライトは構文木を書き換える `rehype-highlight` を使い、HTML 文字列を返すハイライター（埋め込みが要るもの）は使わない。SVG の文字列を返すライブラリ（mermaid）は、DOM に入れず `data:image/svg+xml` の URI にして `<img>` で表示する。HTML レポート・PDF・DOCX・HTML スライドの書き出し（#36）は構文木（hast・文書の中間の形）から作り、本文の生の HTML は文字として出し、危ない URL のリンク・本文の画像を外し、スクリプトを入れない（`docs/05-security.md`「XSS対策」）。
- **CSP**: `next.config.ts` で CSP ヘッダーを設定する。
- **添付画像**: 形式はクライアントの申告ではなく中身の先頭（マジックナンバー）で判定し、PNG / JPEG だけを保存する（SVG を受け付けない）。配信は判定済みの `Content-Type` と `X-Content-Type-Options: nosniff` で返す（#6。`docs/05-security.md`「添付画像」）。

## シークレット管理

- ローカル環境: `front/.env.local`（`.gitignore` に追加済み）
- シークレット・認証情報をコードにハードコードしない
- **`.gitignore` だけに頼らない**: `.gitignore` は未追跡ファイルにしか効かない。追跡された秘匿ファイルは CI の Secret scan（`.github/workflows/secret-scan.yml`）で検出して落とす。検出対象・除外は同ワークフローが唯一の真実
- **混入したらローテーション**: push 済みのファイルは追跡を外しても履歴に残るため、含まれる鍵・トークンを必ずローテーションする（履歴の書き換えでは対処にならない）
- テンプレート（`.env.example` 等）を追加する場合は、Secret scan の除外に当たる名前（`.example` / `.sample` / `.template` / `.dist`）にする

## ローカルの補助サービス（Docker）

- `docker-compose.yml` のサービスのうち、アプリだけが使うもの（SearXNG 等）は **`127.0.0.1` だけに公開する**。特に、同時アクセスの制限を止めたサービスを外へ公開しない
- サービスの秘密鍵が要る場合は、リポジトリにも `.env` にも置かず、起動時に生成するなどして渡す（SearXNG の `SEARXNG_SECRET` の扱い。`docs/05-security.md` 参照）
- **ローカルのファイルを読むツールは、許可したフォルダの中だけに限る**（#148）: 読んでよいフォルダは `LOCAL_FILE_ROOTS` で明示し、未設定ならツールを登録しない。パスは `realpath` で実体にしてから包含を判定する（文字列の前方一致で判定しない）。`.env`・鍵・`.ssh` などの秘匿ファイルは、許可したフォルダの中でも読ませない（範囲は Secret scan と揃える）。ローカルのファイルを読んだ応答の中では、外部と通信するツールを実行しない（`docs/05-security.md`「ローカルのファイルのツール」）
- **ファイルの書き込みは毎回の承認を挟む**（#148 Phase A2）: 書き込みのツールは差分を見せて利用者が許可してから書く（一括の許可は作らない）。書き込んでよい場所は `LOCAL_FILE_WRITE_ROOTS`（`LOCAL_FILE_ROOTS` の中だけ）に限り、`.git` の中と秘匿ファイルには書かせない。承認した内容と書く内容を同じにする（準備で作った中身を書き、承認の間に変わっていれば書かない）（`docs/05-security.md`「ファイルの書き込み」）
- **コマンドの実行は毎回の承認を挟み、シェルを介さない**（#148 Phase B）: 実行してよいプログラムは `LOCAL_COMMANDS` で明示し（未設定ならツールを登録しない）、シェルと別のプログラムを起動するもの（`env`・`sudo`・`xargs` 等）は書いても外す。引数の配列で `shell: false` で実行し、作業フォルダは `LOCAL_FILE_WRITE_ROOTS` の中だけに限る。コマンドに渡す環境変数は絞り、アプリの設定を渡さない。止めるときはプロセスグループごと止める（`docs/05-security.md`「コマンドの実行」）
- **GitHub のツールは `gh` の引数をアプリが組み立て、書き込みは毎回の承認を挟む**（#148 Phase C）: 扱ってよいリポジトリは `GITHUB_REPOS` で明示し（未設定ならツールを登録しない）、モデルの書いた値は検証してから決まった形（`pr`・`issue` の `list`・`view`・`diff`・`comment`・`create`、`repo view`）の引数に入れる（`gh api`・`gh auth` 等に届かせない）。値は `--flag=値` で渡す。読むツールは承認なしで、読んだ応答の中では外部と通信するツールを止める（非公開のリポジトリの内容を外へ送らせない）。コメント・PR の作成は、送る本文を Markdown として描かずに見せて承認を求める。トークンはアプリで持たず（`gh auth login` に任せる）、`gh` に渡す環境変数は `run_command` と同じく絞る（`docs/05-security.md`「GitHub のツール」）
- **ブラウザのツールは通信をアプリの中のプロキシに通し、接続ごとに宛先を判定する**（#149）: `BROWSER_ENABLED=true` のときだけ登録する。Chromium のすべての通信（転送の先・ページの中の `fetch`・WebSocket を含む）をプロキシに通し、名前を引いて判定したアドレスへそのまま接続する（Playwright の `route` は転送の連鎖を通らないため使わない）。プライベートのアドレスは `BROWSER_LOCAL_ORIGINS` に書いた開発サーバーだけを開け、このアプリ自身（ループバックのアプリのポート）は書いても開かない。手元の開発サーバーへの接続は、最上位のページが手元の開発サーバーのときだけ通す（公開のページのスクリプト・iframe・転送から手元を読ませない）。`http`・`https` 以外は開かない。セッションは応答ごとの空のコンテキスト（利用者の Cookie を使わない・ダウンロードしない）。手元の開発サーバーのページを読んだ後は、その応答で外部と通信するツールを止め、プロキシも公開の Web へ接続しない。画像を読めないモデルにはスクリーンショットのツールを渡さない。クリック・入力・選択（#149 Phase C）は毎回の承認を挟み、承認カードには参照から引いた実際の要素を出す（モデルの説明は出さない）。承認を待つ間にページ・要素が変わっていたら操作しない。手元の情報を読んだ後は公開のページを操作せず、パスワード欄には入れない。利用者へ見せる画面（#200）はモデルへ渡さず、承認カードの要素の枠は参照から引いた要素の位置から描く。画面は assistant の添付画像として保存し、保存 API で中身の先頭から PNG / JPEG を判定する（1 回の応答で 20 枚まで）（`docs/05-security.md`「ブラウザのツール」）
- **モデルの出力を外部の取得の起点にさせない**: 応答の本文を渡すサービス（PlantUML サーバー等）は、本文に書かれた URL・ファイルを読みに行かない設定で動かす（PlantUML は `PLANTUML_SECURITY_PROFILE=SANDBOX`）
